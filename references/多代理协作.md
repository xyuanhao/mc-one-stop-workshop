# 多代理协作 —— 大任务并行，小任务别折腾

> 目标：当模组 / 整合包任务真的能拆成相互独立的工作包时，主代理同时派出多个子代理；
> 用**文件所有权 + 依赖 DAG + 独立验收**防止“人多手杂”。子代理只负责各自工作包，
> **主代理永远负责规划、集成、最终验证和交付**，不能把交付责任外包出去。

## 1. 什么时候开，什么时候别开

满足下面**全部条件**才拆：

1. 至少有 **2 个可独立完成的工作包**，不是把同一件事硬切成“想一半 / 写一半”；
2. 每个包都有明确的产物、可写文件范围和独立验收判据；
3. 包之间没有频繁的来回依赖，接口可以先钉死；
4. 并行节省的是实际等待或独立工作量，而不是只多造几份报告。

典型该拆：多个内容系统（物品 / 方块 / 生物）、代码与独立贴图资源、迁移时分模块修 API、
整合包的任务书与数据包、互不依赖的生态调查、只读代码勘察与方案设计。
**2–4 个执行代理通常足够**；只有任务确实更多且完全独立时再增加，别开“代理农场”。

下面情况**保持单线**：

- 加一个物品、改几行代码、修一个报错、跑一个检查；
- 多个包要反复改同一注册类、同一任务书生成器、同一构建脚本；
- 版本 / 加载器 / 整体方案还没定，或用户决策会推翻全部下游；
- 下一步强依赖上一步结果（先定位根因才能知道改哪里）；
- 只剩 build / runServer / smoke 等共享环境验证。

## 2. 固定流程：规划 → 任务板 → 并行 → 集成 → 总验收

### 2.1 主代理先钉住公共契约

在派代理前完成：目标 MC 版本与加载器、模组规划书、目录与命名、公共 API / 数据格式、
注册 id 清单、资源清单、最终验证矩阵。**不要让子代理各自决定这些全局事实。**

为每项工作包创建任务并维护状态；用 `references/多代理协作.md` 的规则拆分，再用
`scripts/多代理任务板.py` 把计划落成 JSON。计划是协调用的轻量文件，不替代模组规划书。

### 2.2 每个子代理只拿一个自包含工作包

Agent prompt 必须写全（子代理看不到主对话）：

| 字段 | 必须写清 |
|---|---|
| 目标 | 做什么、不做什么；对应规划书哪几条 |
| 环境 | 工程绝对路径、MC / loader / Java、当前基线 |
| 所有权 | **允许写的文件或目录**；此外一律只读 |
| 接口 | 可依赖的公共类 / id / 数据格式，禁止私自改公共契约 |
| 验收 | 要运行的命令、通过条件、必须保留的证据 |
| 回报 | 实际改了哪些文件、命令与结果、未完成项、需要主代理处理的接口 |

优先给 `general-purpose` 一个完整实现包；只读调查用 `Explore`，方案设计用 `Plan`。
**只读代理不得被要求改文件。** 无依赖的执行包在同一个消息里并行派出；有依赖的等上游完成。

### 2.3 文件所有权是硬边界

- 两个执行代理**不得写同一文件**；一个写 `A.java`、另一个写 `B.java` 才算真正独立。
- `ModItems` / `ModBlocks` / `ModEntities`、主 mod 类、创造栏、统一 datagen 入口、
  `build.gradle`、`gradle.properties`、任务书总生成器，默认归**主代理集成**。
- 子代理可以提供“待集成片段”或独立实现类，但不要多人抢写聚合注册表。
- 共享目录可以按**不重叠子目录**分，例如 `textures/item/tools/` 与 `textures/item/armor/`；
  不能笼统地把整个 `src/` 同时交给两个人。
- 只读研究可并行；它若后来转实现，必须重新确认所有权再开工。

`多代理任务板.py check` 会检查重复文件、目录包含冲突、依赖悬空和依赖环。
**脚本通过只是结构合法，不代表分工在语义上合理**，主代理仍要审一遍。

### 2.4 回收与集成

每个代理返回后，主代理必须亲自：

1. 对照允许写清单核对真实 diff，发现越界先退回 / 修正，不直接合并；
2. 审查产物和测试输出，不能只看“已完成”三个字；
3. 将接口变更先写回公共契约，再集成公共注册、语言索引、构建配置；
4. 更新任务状态；失败或阻塞项保留为未完成，另派修复包或主代理接手；
5. 全部集成后跑整工程检查，不能把各包的局部成功直接当成整体成功。

**冲突处理**：先停写冲突区 → 以公共契约为准 → 由主代理或唯一指定代理合并 →
重跑受影响工作包和整体验证。禁止让两个代理互相覆盖到“最后写入者获胜”。

### 2.5 最终验证不因并行而减少

模组仍走：`检查工程.py` → `gradlew build` → 必要的 `runServer` / RCON 行为验证 →
`游戏内测试.py smoke`。整合包仍走静态七项 + 真实客户端进世界证据。
构建目录、游戏窗口、RCON 端口、存档和测试世界是**共享状态**，默认由主代理串行操作；
不要让多个代理同时跑 `gradlew`、同时启动客户端 / 服务端或改同一个世界。

## 3. 任务板格式与命令

最小示例（两个实现包 + 主代理集成）：

```json
{
  "schema_version": 1,
  "project": "绿宝石工艺",
  "tasks": [
    {
      "id": "tools",
      "title": "实现工具行为",
      "owner": "agent:tools",
      "writes": ["src/main/java/com/yuan/emeraldsword/item/"],
      "depends_on": [],
      "acceptance": ["工具行为单元场景通过", "未修改注册聚合类"]
    },
    {
      "id": "textures",
      "title": "制作工具贴图",
      "owner": "agent:textures",
      "writes": ["src/main/resources/assets/emeraldsword/textures/item/tools/"],
      "depends_on": [],
      "acceptance": ["贴图尺寸与 alpha 合格", "离线预览无缺失"]
    },
    {
      "id": "integrate",
      "title": "统一注册并整体验证",
      "owner": "main",
      "writes": ["src/main/java/com/yuan/emeraldsword/registry/"],
      "depends_on": ["tools", "textures"],
      "acceptance": ["build 通过", "runServer 行为验证通过", "smoke 退出码 0"]
    }
  ]
}
```

规则：路径相对工程根；`/` 结尾表示整个目录；只读任务写 `"readonly": true` 且不得声明 `writes`。
`owner` 只是协调标签，真正约束来自主代理的 prompt 与实际 diff 复核。

```bash
# 生成可编辑模板（拒绝覆盖已有文件）
python scripts/多代理任务板.py init 协作计划.json --project 绿宝石工艺

# 派代理前：结构、依赖、文件冲突检查；0 才能开始并行
python scripts/多代理任务板.py check 协作计划.json

# 合并前：检查结构 + 每个任务的状态与证据；全部 completed 且 evidence 非空才为 0
python scripts/多代理任务板.py check 协作计划.json --delivery

# 工具自检：合法样本通过，冲突 / 环 / 缺证据等坏样本必须被拦住
python scripts/多代理任务板.py --selftest
```

任务执行后可在对应任务里补 `"status": "completed"` 与
`"evidence": ["实际产物或验证报告路径", "构建 / 测试命令结果"]`。
`--delivery` 只验证任务板声明完整，**仍须主代理实际读取证据并重跑整体验证**。

退出码统一：`0 = 通过 / 1 = 计划或交付门禁未通过 / 2 = 参数、路径或 JSON 错误`。

## 4. 模组与整合包的常用拆法

| 场景 | 可并行工作包 | 主代理独占 |
|---|---|---|
| 多内容 mod | 独立物品行为、独立生物 / 模型、贴图资源、只读 API 调查 | 注册聚合、公共配置、build、统一 datagen、smoke |
| 大版本迁移 | 按互不重叠包修代码、资源目录迁移、只读 API 差异调查 | 构建脚本与版本号、共享基类、最终逐级迁移与双端验证 |
| 整合包内容 | 任务书章节蓝图、独立数据包、资源包 / 汉化、模组生态调查 | 清单与依赖闭包、同一生成器、实例写入、打包与实机证据 |
| 疑难排障 | 多个**只读**假设调查（日志 / 字节码 / 资源） | 根因裁决、实际修改、共享环境复现与回归 |

> 核心原则：**按产物边界拆，不按“再来一个人”拆；按 DAG 并行，按整体验收交付。**

## 0. 三类清单：先分清"哪些文件怎么进包"

所有格式本质都是 **ZIP + 一个 manifest + 一个 overrides 目录**，区别只在 manifest 的 schema：

```
mypack.{zip,mrpack,gdlpack}
├── <manifest>.json     ← 只有这个必须被启动器认识
├── overrides/          ← 直接解压进实例的内容（配置/脚本/世界/非平台 mod）
└── modlist.html        ← CF 独有、可选：人类可读的 mod 列表
```

导出时的文件分三类（XMCL 的分类法，通用）：
1. **Override 文件**——始终塞进 zip：配置文件、saves、scripts、以及**查不到平台元数据的文件**；
2. **引用文件**——只写进 manifest（CF 用 projectID/fileID，mrpack 用下载 URL + hash），由客户端下载；
3. **Backfill 文件**——元数据缺失，尝试用指纹（CF murmur2）/ hash（Modrinth sha1）反查补齐，查不到就降级为 override。

> 这条分类解释了为什么「本地 jar 放 `overrides/mods/`」是通用做法：平台查不到的文件**只能**走 overrides。

## 1. CurseForge（`.zip`，`manifest.json`）

```json
{
  "minecraft": {
    "version": "1.20.1",
    "modLoaders": [{ "id": "forge-47.2.0", "primary": true }]
  },
  "manifestType": "minecraftModpack",
  "manifestVersion": 1,
  "name": "Example Pack",
  "version": "1.0.0",
  "author": "someone",
  "projectID": 289267,
  "files": [
    { "projectID": 238222, "fileID": 5246076, "required": true }
  ],
  "overrides": "overrides"
}
```

| 字段 | 说明 |
|---|---|
| `minecraft.version` | 目标 MC 版本 |
| `minecraft.modLoaders[].id` | `<loader>-<版本>`，如 `forge-47.2.0` / `neoforge-21.1.219` / `fabric-0.16.5` |
| `minecraft.recommendedRam` | 可选，建议内存 MB |
| `files[]` | 每个 mod 用 **CF 的 projectID + fileID** 引用；`required` 表示必需 |
| `projectID` | **包自身**在 CF 的项目 ID（发布到 CF 才有） |
| `overrides` | 覆盖目录名，通常 `"overrides"` |

**关键机制与风险**：
- `overrides/` 在 **mod 下载完成之后**解压进实例——所以本地 jar 必须走 `overrides/mods/`，
  放 zip 根 `mods/` 会被启动器静默忽略（PCL2 实测如此）。
- **files 引用的是 CF 上的文件 ID，作者删文件 = 安装失败**（"file not found"）。
  所以本地全量分发（files 留空 + overrides/mods/）对国内分享最稳，代价是包体积。
- CF 官方启动器导入**需要文件托管在 CurseForge**；PCL2 / HMCL / Prism 对 files 为空 + overrides 全量分发的包能正常导入。
- `modlist.html`（可选）是 CF 独有的人类可读 mod 列表，很多包会附带。

## 2. Modrinth（`.mrpack`，`modrinth.index.json`）

```json
{
  "formatVersion": 1,
  "game": "minecraft",
  "versionId": "1.0.0",
  "name": "Example Pack",
  "summary": "A short tagline",
  "dependencies": { "minecraft": "1.21.1", "fabric-loader": "0.16.5" },
  "files": [
    {
      "path": "mods/sodium-fabric-0.6.0.jar",
      "hashes": { "sha1": "...", "sha512": "..." },
      "env": { "client": "required", "server": "unsupported" },
      "downloads": ["https://cdn.modrinth.com/data/AANobbMI/versions/.../sodium.jar"],
      "fileSize": 1234567
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `formatVersion` | int | 恒为 1 |
| `game` | string | 恒为 `"minecraft"` |
| `dependencies` | map | `minecraft` + 加载器键：`forge` / `neoforge` / `fabric-loader` / `quilt-loader`（通常只写一个加载器） |
| `files[].path` | string | 相对安装路径，**必须正斜杠**（mrpack-install 有反斜杠兼容 hack，说明这是高频错误） |
| `files[].hashes` | map | `sha1` 与 `sha512`（都写最稳） |
| `files[].env` | map | `client` / `server` 各取 `required` \| `optional` \| `unsupported` |
| `files[].downloads` | []string | HTTPS 下载 URL 数组；**hash 不匹配是硬性拒绝安装**，不像 CF 只警告 |
| `files[].fileSize` | int | 字节数，可选但建议写 |

**官方三级 overrides（2026 官方支持，比 CF 更灵活）**：
- `overrides/` —— 两端都应用
- `server-overrides/` —— **仅服务端**，在 overrides 之后叠加覆盖（省得再做单独服务端包）
- `client-overrides/` —— 仅客户端，同样叠加
三个都是可选的；层叠顺序 = overrides → server/client-overrides（后者覆盖前者）。

> `env.server: "unsupported"` 比"把客户端 mod 塞服务端"重要得多——**服务端崩最常见的原因就是
> 把 client-only mod 复制进了服务端**。写 mrpack 时客户端类 mod（光影、小地图、HUD）应标 `server: "unsupported"`。

## 3. Prism / MultiMC（`mmc-pack.json`）

```json
{
  "formatVersion": 1,
  "components": [
    { "uid": "net.minecraft", "version": "1.20.1", "cachedName": "Minecraft" },
    { "uid": "net.minecraftforge", "version": "47.2.0", "cachedName": "Forge" }
  ]
}
```
组件式：MC 与加载器都是"组件"。`整合包体检.py` 会读 `mmc-pack.json` 判断版本（实例配置优先级最高）。

## 4. GDLauncher（`.gdlpack`，`gdlpack.json`）—— 知道有这东西

只存**内容哈希**（sha512/sha1/murmur2），安装时拿 hash 去 CF 和 Modrinth 两头解析，哪个有从哪个下。
好处：跨平台、无 URL 失效、逐字节校验。国内用得少，但遇到 `.gdlpack` 要知道它是 zip + gdlpack.json + overrides。

## 5. 各格式取舍速查

| 诉求 | 选 |
|---|---|
| 国内分享、要对方一键导入 | **CF zip（全量本地分发）** |
| 想要体积小、mod 都在 Modrinth 上 | **mrpack（--online 反查，files 只写引用）** |
| 需要服务端包 / 客户端包分离 | **mrpack**（server-overrides / client-overrides） |
| 给 Prism 用户 | mrpack 或 mmc-pack 实例导出 |
| 只做备份迁移 | instance zip（原布局整包） |

## 6. 我们的脚本对应

`制作整合包.py` 三种输出与本文的对应：
- `curseforge` → §1，files 留空 + `mods/*.jar` 同时放 `overrides/mods/`（兼容性最强）
- `mrpack` → §2，默认全量本地分发（jar 进 `overrides/mods/`），`--online` 时改写成 files 引用（带 sha1 + downloads）
- `instance` → 原布局整包，无 manifest（PCL 备份式）

**已实现**：CF（files 留空 + `overrides/mods/`）、mrpack（本地分发 + `--online` 引用，
含 sha1 / downloads / **fileSize**）、instance（原布局整包）。

**格式支持但脚本未实现**：`server-overrides` / `client-overrides`（做服务端包时才有价值）、
`modlist.html`（CF 独有的人类可读清单）、`projectID`（发布到 CF 才有）、
`files[].hashes.sha512`（目前只写 sha1，官方建议双写）。
需要时再补——前两个 + sha512 是最可能用上的。

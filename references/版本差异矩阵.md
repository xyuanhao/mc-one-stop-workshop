# Minecraft Java 版模组开发 · 版本差异矩阵（1.20.1 → 最新）

> 本文档供「AI 自动生成可编译 MC 模组」的 skill 使用。目标是让 AI 在写代码前，能一眼查到**指定版本该怎么写**。
> 编制日期：**2026-09-04**。当前最新稳定版：**26.2（2026-06-16）**。
>
> 来源标注规则：每个关键事实后标注 `来源: <URL>` 与版本号。凡无法从权威来源 100% 确认的版本分界点，标注 **⚠️ 待验证 + 最可能范围**，切勿照抄。

---

## 0. 最重要的发现（先读这段）

1. **版本号体系已变**：Mojang 从 2025-12 起弃用「1.21.x」递增，改用 **年份.更新（year.drop）** 体系。最新稳定版是 **26.2**，不是 1.22。
   - 1.21.x 的最后一个是 **1.21.11（2025-12-09）**。
   - 之后是 **26.1（Tiny Takeover，2026-03-24）→ 26.2（Chaos Cubed，2026-06-16）**，26.3 预计 2026 Q3。
   - 来源: https://minecraft.wiki/w/Java_Edition_version_history ，https://minecraft.wiki/w/Java_Edition_26.1

2. **很多 1.20.1 教程里的写法在新版本直接编译失败**（见第 4 节反模式清单）。本 skill 生成代码时，务必按目标版本选写法。

3. **加载器格局**：NeoForge 在 **1.20.1** 时从 Forge 分叉；1.20.2+ 两生态完全分离；**1.21+ 新模组首选 NeoForge**（见第 5、6 节）。

## 3. 破坏性变更详解（面向 mod 开发者）

每个变更给出 **旧写法 → 新写法** 对照，并标注**发生版本**与**来源**。

### 3.1 物品 NBT → Data Components（物品栈数据模型重写）
**发生版本：1.20.5**（来源: https://docs.fabricmc.net/zh_cn/develop/items/custom-data-components ，https://neoforged.net/news/21.0release ）

旧（1.20.4 及之前）：
```java
// 用 NBT 存自定义数据
ItemStack stack = new ItemStack(ModItems.WAND);
stack.getOrCreateTag().putInt("charges", 5);
int charges = stack.getTag().getInt("charges");
```

新（1.20.5+）：用 `DataComponentType`（注册在 `BuiltInRegistries.DATA_COMPONENT_TYPE`）
```java
// 注册组件
public static final DataComponentType<Integer> CHARGES = Registry.register(
    BuiltInRegistries.DATA_COMPONENT_TYPE,
    Identifier.fromNamespaceAndPath(MOD_ID, "charges"),
    DataComponentType.<Integer>builder().persistent(Codec.INT).build()
);

// 读取/写入/移除
int c = stack.getOrDefault(CHARGES, 0);   // 旧: stack.getTag().getInt(...)
stack.set(CHARGES, c + 1);               // 旧: tag.putInt(...)
stack.remove(CHARGES);                   // 旧: tag.remove(...)
boolean has = stack.has(CHARGES);        // 旧: tag.contains(...)
```
> 注：`/give` 语法也变为 `give @p mod:item[mod:charges=5]`（方括号组件，不再是 NBT 字符串）。
> Fabric 文档页标题为“26.2”说明该页当前版本；写法自 1.20.5 起稳定。

### 3.2 物品模型定义（models/item/*.json → assets/<ns>/items/*.json）
**发生版本：1.21.4**（引入 `assets/<ns>/items/*.json` 的 item model 定义；来源: https://www.minecraftforum.net/news/60939-java-edition-minecraft-1-21-4 ，https://zh.minecraft.wiki/w/物品模型映射 ）

旧（≤1.21.3，重定向式）：
```json
// assets/minecraft/models/item/diamond.json 里用 "overrides": [{ "predicate": {"custom_model_data": 1}, "model": "..." }]
{ "parent": "item/generated", "textures": {...}, "overrides": [ {"predicate":{"custom_model_data":1},"model":"item/my_model"} ] }
```

新（1.21.4+，声明式 item model）：
```json
// assets/<namespace>/items/<id>.json
{
  "model": {
    "type": "minecraft:condition",
    "property": "minecraft:broken",
    "on_false": { "type": "minecraft:model", "model": "minecraft:item/elytra" },
    "on_true":  { "type": "minecraft:model", "model": "minecraft:item/elytra_broken" }
  }
}
```
可用 `type`：`minecraft:model` / `composite` / `condition` / `select` / `range_dispatch` / `special` / `bundle/selected_item` / `empty`；谓词如 `minecraft:custom_model_data`、`minecraft:component`、`minecraft:keybind_down` 等。
> ⚠️ 过渡细节：1.21.2–1.21.3 用 `range_dispatch` 仍写在 `models/item/*.json`；1.21.4 起迁移到 `assets/<ns>/items/*.json`（来源: https://deepwiki.com/jhqwqmc/craft-engine/10.2-content-configuration-examples ）。

### 3.3 Identifier 构造方式（new Identifier → Identifier.of）
**Fabric（Yarn）/ Mojang 映射差异**：
- **Fabric 1.21 起**：`new Identifier("mod","id")` 应改为 `Identifier.of("mod","id")`。
  ```java
  // 旧（≤1.20.6）
  Identifier id = new Identifier("mymod", "my_item");
  // 新（1.21+）
  Identifier id = Identifier.of("mymod", "my_item");   // 或 Identifier.fromNamespaceAndPath(...)
  ```
  来源: https://fabricmc.net/wiki/tutorial:blocks （diff 显示 1.21 用 `Identifier.of`）
- **NeoForge / Mojang 映射 1.21 起**：`ResourceLocation` 构造函数变 **private**，改用静态工厂：
  ```java
  // 旧（1.20.6 及之前）
  new ResourceLocation("mymod", "my_item");
  new ResourceLocation("mymod:my_item");
  // 新（1.21+）
  ResourceLocation.fromNamespaceAndPath("mymod", "my_item");  // 等价旧双参构造
  ResourceLocation.parse("mymod:my_item");                    // 等价旧单参构造
  ResourceLocation.withDefaultNamespace("my_item");            // 等价旧("minecraft", ...)
  ResourceLocation.tryBuild(...);   // 失败返回 null 而非抛异常
  ```
  来源: https://neoforged.net/news/21.0release

### 3.4 注册表系统重写（Registry / Registries / Holder / 1.21.2）
**1.21（Fabric 移除 `Registry` 类，改用 `Registries`）** + **1.21.2 注册表层重构**：
- Fabric 1.21：
  ```java
  // 旧（≤1.20.6）
  Registry.register(Registry.BLOCK, new Identifier("mod","b"), BLOCK);
  // 新（1.21+）
  Registry.register(Registries.BLOCK, Identifier.of("mod","b"), BLOCK);
  ```
  来源: https://fabricmc.net/wiki/tutorial:blocks
- Fabric 1.21.2：`Registry` 实现 `RegistryEntryLookup`，方法改名：
  ```java
  // 旧 → 新（1.21.2+）
  registry.getEntry(key)      → registry.getOptional(key)
  registry.entryOf(key)       → registry.getOrThrow(key)
  registry.getOrThrow(key)    → registry.getValueOrThrow(key)
  registry.getOrEmpty(key)    → registry.getOptionalValue(key)
  registry.getEntryList(tag)  → registry.getOptional(tag)
  // DynamicRegistryManager#get / WrapperLookup#getWrapperOrThrow → getOrThrow
  ```
  来源: https://fabricmc.net/2024/10/14/1212.html
- 1.21 起 `Holder<Enchantment>` 等被大量方法要求（数据驱动附魔，见 3.10）。

### 3.5 包名路径变更
**结论：`net.minecraft` 与 `com.mojang` 包路径自 1.20.1 至今保持稳定，没有发生 `net.minecraft → 其他` 的批量重命名。**
- NeoForge 文档里提到的 “1.20.2: The package renames” 指的是 **NeoForge 自身内部包**的重构（如 `net.minecraftforge` 相关内部路径调整），**不是 Mojang 的 `net.minecraft`/`com.mojang`**。（来源: https://neoforged.net/news/21.0release ）
- ⚠️ 待验证：Mojang 在 1.20.x 个别类有过内部迁移，但**对 mod 暴露的顶层包名（net.minecraft.*、com.mojang.blaze3d.* 等）未变**。生成代码时无需改 import 前缀。

### 3.6 网络包系统变更（CustomPacketPayload / StreamCodec / FriendlyByteBuf）
**NeoForge：1.20.5 起**（来源: https://neoforged.net/news/20.5release/ ，https://docs.neoforged.net/docs/1.20.6/networking/payload/ ）

旧（1.20.4 及之前，基于 `FriendlyByteBuf` + `SimpleChannel`/`RegisterPayloadHandlerEvent`）：
```java
public record MyData(String name, int age) implements CustomPacketPayload {
    public static final ResourceLocation ID = new ResourceLocation("mymod", "my_data");
    public MyData(FriendlyByteBuf buf) { this(buf.readUtf(), buf.readInt()); }
    @Override public void write(FriendlyByteBuf buf) { buf.writeUtf(name); buf.writeInt(age); }
    @Override public ResourceLocation id() { return ID; }
}
// 注册：event.registrar("mymod").play(MyData.ID, MyData::new, handler -> handler.client(...).server(...))
```

新（1.20.5+，基于 `StreamCodec`）：
```java
public record MyData(String name, int age) implements CustomPacketPayload {
    public static final Type TYPE = new Type(ResourceLocation.fromNamespaceAndPath("mymod", "my_data"));
    public static final StreamCodec<RegistryFriendlyByteBuf, MyData> STREAM_CODEC =
        StreamCodec.composite(ByteBufCodecs.STRING_UTF8, MyData::name,
                              ByteBufCodecs.VAR_INT,     MyData::age,
                              MyData::new);
    @Override public Type type() { return TYPE; }
}
// 注册：RegisterPayloadHandlersEvent → registrar("ver").playBidirectional(MyData.TYPE, MyData.STREAM_CODEC, new DirectionalPayloadHandler(...))
// 发送：PacketDistributor.sendToServer(...) / sendToClient(...)
```
> `FriendlyByteBuf` **仍可用**（作为 `StreamCodec` 的 buffer 类型之一），但旧的 `SimpleChannel`/`readUtf`+构造器式 `CustomPacketPayload` 写法已废弃。Fabric 侧用 `PacketCodec`/`CustomPayload`（1.20.5+，具体 API 见 Fabric Networking）。

### 3.7 方块实体类型 Builder API 变更
**1.21.1（必须 addSupportedBlock）+ 1.21.2（Fabric 移除 `FabricBlockEntityType.Builder`）**：
- 1.21.1：新增方块必须注册支持块
  ```java
  BlockEntityType.SIGN.addSupportedBlock(ModBlocks.TEAL_SIGN);
  ```
  来源: https://fabricmc.net/2024/10/14/1212.html
- 1.21.2（Fabric）：`FabricBlockEntityType.Builder` 被移除，改用（不再废弃的）`FabricBlockEntityTypeBuilder`：
  ```java
  // 旧（≤1.21.1）
  FabricBlockEntityType.Builder.create(MyBE::new, ModBlocks.MY_BLOCK).build(null);
  // 新（1.21.2+）
  FabricBlockEntityTypeBuilder.create(MyBE::new, ModBlocks.MY_BLOCK).build();
  ```
  来源: https://fabricmc.net/2024/10/14/1212.html
> ⚠️ 待验证：NeoForge 侧 `BlockEntityType.Builder` 的 API（如 `Builder.create(...).build(...)`）是否同步变更；NeoForge 文档未明确，建议以 NeoForge 21.x MDK 生成的示例为准。

### 3.8 创造模式物品栏 API 变更
**1.21.2（Fabric）起**：创造标签页用 `FabricItemGroup.builder()`，物品通过 `displayItems((params, output) -> output.accept(...))` 添加（来源: https://docs.fabricmc.net/zh_cn/1.21.11/develop/items/custom-item-groups ）：
```java
public static final ResourceKey<CreativeModeTab> TAB_KEY =
    ResourceKey.create(BuiltInRegistries.CREATIVE_MODE_TAB.key(),
                       Identifier.fromNamespaceAndPath(MOD_ID, "creative_tab"));
public static final CreativeModeTab CUSTOM_TAB = FabricItemGroup.builder()
    .icon(() -> new ItemStack(ModItems.GUIDITE_SWORD))
    .title(Component.translatable("itemGroup.example-mod"))
    .displayItems((params, output) -> {
        output.accept(ModItems.SUSPICIOUS_SUBSTANCE);
        output.accept(ModBlocks.CONDENSED_OAK_LOG);
    })
    .build();
```
> ⚠️ 旧写法 `ItemGroup` 直接 `add()` 或 `Item.Properties().group(...)` 在新版已被 `creative tab` / `DataComponents.CREATIVE_SLOT` 思路取代；1.21 起物品归类更多由 `ItemDisplayContext` 与标签页 `displayItems` 控制。

### 3.9 配方系统（RecipeInput 取代 Container / RecipeDisplay）
**1.21 起**（来源: http://gists.github.com/exdj158/db763f66d3b73d44a50e73a8807b27d2/... ，https://fabricmc.net/2024/10/14/1212.html ，https://docs.blamejared.com/1.21/en/1_21_migration_guide ）

旧（≤1.20.6）：
```java
public class MyRecipe implements Recipe<Container> {
    public boolean matches(Container inv, Level level) { ItemStack s = inv.getItem(0); ... }
}
```
新（1.21+）：`Container` → `RecipeInput`（方法 `getItem(i)` / `size()` / `isEmpty()`）：
```java
public class MyRecipe implements Recipe<RecipeInput> {
    public boolean matches(RecipeInput input, Level level) { ItemStack s = input.getItem(0); ... }
}
```
- **1.21.2（Fabric）额外**：配方数据生成器 `generate(...)` → 重写 `getRecipeGenerator(registries, exporter)` 返回 `RecipeGenerator`（来源: https://fabricmc.net/2024/10/14/1212.html ）：
  ```java
  // 旧
  public void generate(RecipeExporter exporter) { offerPlanksRecipe2(exporter, SIMPLE_BLOCK, ...); }
  // 新
  protected RecipeGenerator getRecipeGenerator(RegistryWrapper.WrapperLookup registries, RecipeExporter exporter) {
      return new RecipeGenerator(registries, exporter) {
          @Override public void generate() { offerPlanksRecipe2(SIMPLE_BLOCK, ...); }
      };
  }
  ```
- **1.21.2 配方 ID 改为 `RegistryKey`，客户端只收到 `RecipeDisplayEntry`（整数网络 ID），不再能直接访问 `Recipe` 实例**（来源: https://fabricmc.net/2024/10/14/1212.html ）。

### 3.10 附魔/属性/药水数据驱动改造
**1.21（附魔数据驱动）**（来源: https://neoforged.net/news/21.0release ，http://gists.github.com/exdj158/... ）：
- 附魔从静态注册表变为**数据包注册表**。方法签名普遍改为接收 `Holder<Enchantment>`（从 level 的 `RegistryAccess` 取），`Enchantments` 类的字段全部是 `ResourceKey`。
  ```java
  // 旧
  itemStack.addEnchantment(Enchantments.SHARPNESS, 3);  // 直接 Enchantment
  // 新（1.21+，需用 Holder）
  Holder<Enchantment> sharp = registryLookup.lookupOrThrow(Registries.ENCHANTMENT).getOrThrow(Enchantments.SHARPNESS);
  itemStack.addEnchantment(sharp, 3);
  // 判断效果改用 EnchantmentEffectComponents，而非直接 level 检查
  ```
- 属性修饰符（`AttributeModifiers`）1.21 起用 `ResourceLocation` 唯一标识修饰符（取代旧 String UUID）：
  ```java
  // 旧: addAttributeModifier(slot, UUID, amount, op)
  // 新: addAttributeModifier(slot, ResourceLocation.fromNamespaceAndPath("mod","modifier"), amount, op)
  ```
  来源: http://gists.github.com/exdj158/db763f66d3b73d44a50e73a8807b27d2/...
- 药水/效果（`MobEffect`）若干方法 1.21.2 改为接收 `Holder`（详见 ChampionAsh 1.21.2 primer）。

### 3.11 Forge → NeoForge 分叉点
**分叉时间：2023-07-12**，由 cpw 与多数原 Forge 团队创建 NeoForge（来源: https://www.g-portal.com/wiki/en/minecraft-neoforge/ ，https://neoforged.net/news/2024-retrospection/ ）。
- 分叉时最新 MC 版本为 **1.20.1**，故 NeoForge 先出了 20.1.x 构建，但很快**放弃 1.20.1** 聚焦 1.21。
- **1.20.1 是 Forge 与 NeoForge 模组唯一互通的版本**（NeoForge 20.1 可加载 Forge 1.20.1 模组）。
- **1.20.2 起两生态完全分离**，不可混用 jar。
- Forge 后续仍发布了若干版本（镜像显示至 1.21.4），但 2026 年新开发事实标准是 NeoForge。
> ⚠️ 待验证：Forge 确切“停止维护”版本号。社区镜像显示 Forge 至少到 1.21.4（54.0.34），但“事实停更”叙事指向 1.20.4/1.20.6。稳妥建议：新模组不要依赖 Forge 在 1.21+ 的可用性。

### 3.12 Loot table / advancement / tag 格式变化
- **1.21 文件夹去复数（depluralization）**（来源: https://neoforged.net/news/21.0release ，https://docs.blamejared.com/1.21/en/1_21_migration_guide ）：
  ```
  旧 → 新
  tags/blocks    → tags/block
  tags/entity_types → tags/entity_type
  tags/fluids    → tags/fluid
  tags/game_events → tags/game_event
  tags/items     → tags/item
  recipes        → recipe
  advancements   → advancement
  structures      → structure
  loot_tables     → loot_table
  predicates       → predicate
  item_modifiers   → item_modifier
  functions        → function
  ```
- **1.21.2（Fabric）**：`LootTables#EMPTY` 被移除（用 `Optional` 表示“无”）；`LootContextParameter`→`ContextParameter`、`LootContextType`→`ContextType`（来源: https://fabricmc.net/2024/10/14/1212.html ）。
- 1.21.4+ 物品模型系统变化间接影响 loot 表展示逻辑，但 loot 表 JSON 结构本身未大改（除 1.21.5 起部分组件谓词）。
- ⚠️ 待验证：advancement `criteria` 的具体字段变更（如 1.21.2 的 `minecraft:killed_by_crossbow → killed_by_arrow`、`container lock` 改为 item predicate），建议以目标版本的 Minecraft Wiki “Advancements” 页为准。

### 3.13 渲染相关变更
- **`GuiGraphics`**：1.19.4/1.20 引入并取代大量 `PoseStack` 直接绘制；1.20+ 的 HUD/物品/方块实体渲染均走 `GuiGraphics`。
- **1.21.2（Fabric）实体渲染重构**：`EntityRenderer` 增加类型参数 `S extends EntityRenderState`，渲染不再直接访问 `Entity`，而是 `createRenderState` → `updateRenderState` → `render(S state, ...)`（来源: https://fabricmc.net/2024/10/14/1212.html ）。旧教程里 `render(T entity, ...)` 直接读字段的写法失效。
- **1.21.2（Fabric）Shader**：`CoreShaderRegistrationCallback` 被移除，资源包可直接加载 mod 的 core shader。
- **1.21.6 渲染重构**：所有 core shader uniform 改为 **uniform block**；`Global` uniform 可在任意 shader 定义；**所有 JSON 以严格模式解析**（来源: https://minecraft.wiki/w/Resource_Packs ，25w16a/25w17a 条目）。
- **1.20.5/1.21 顶点系统重写**：`VertexConsumer` 通过 `MultiBufferSource#getBuffer(RenderType)` 或 `Tesselator#begin(...)` 获取；`#addVertex(...).setUv(...).setColor(...)` 链式；`#endVertex` 不再存在；`BufferBuilder#end` → `buildOrThrow()` + `BufferUploader.drawWithShader(...)`（来源: http://cola.dany.ddnsfree.com/ChampionAsh5357/d895a7b1a34341e19c80870720f9880f ）。
- **26.1**：客户端渲染类完全去混淆（与服务器一致）。

### 3.14 语言文件 / 资源包格式变化
- 语言文件位置不变：`assets/<ns>/lang/<locale>.json`（如 `en_us.json`、`zh_cn.json`）。
- **1.21.6 起 JSON 严格解析**：`pack.mcmeta`、lang、模型等所有 JSON 容错降低（来源: https://minecraft.wiki/w/Resource_Packs ，25w18a “All JSON files are now parsed in strict mode”）。旧写法里多余的逗号、注释（非标准 JSON）会直接报错。
- **1.21.9 起 pack_format 用小数 + `min_format`/`max_format`**：
  ```json
  // 旧（≤1.21.8）
  { "pack": { "pack_format": 64, "description": "..." } }
  // 新（1.21.9+）
  { "pack": { "pack_format": 69.0, "min_format": 69.0, "max_format": 69.0, "description": "..." } }
  ```
  来源: https://minecraft.wiki/w/Resource_pack_format

### 9.3 NeoForge 26.1 的 API 变更（官方博客实测）

**① `ItemStack` 实例化需要注册表已加载**
```java
// 由于 data components 工作方式变化，新建 ItemStack 需要注册表已加载。
// 注册表加载前（配方等数据文件中）用 ItemStackTemplate：
//   ItemStackTemplate = 记录(item holder, count, data component patch)
//   模板不能为空；需要"空"时用 null，即 @Nullable ItemStackTemplate
ItemStack stack = template.create();                          // 模板 → 栈
ItemStackTemplate t = ItemStackTemplate.fromNonEmptyStack(stack); // 非空栈 → 模板
// 辅助方法
stack.matches.isSameItemSameComponents(stack, template);
resource.matches(template);
// 流体同理：FluidStack/FluidResource 需要注册表，新增 FluidStackTemplate
```

**② `GuiGraphics` 改名**（渲染持续重构中）

| 1.21.11 | 26.1 |
|---|---|
| `Screen#render` | `Screen#extractRenderState` |
| `Screen#renderBackground` | `Screen#extractBackground` |
| `AbstractContainerScreen#renderBg` | `Screen#extractBackground` |
| `AbstractContainerScreen#renderLabels` | `AbstractContainerScreen#extractLabels` |

> ⚠️ **26.1 自定义 Screen 的两个隐形坑（2026-09-27 面板 mod 实测）**：
>
> 1. **`Screen` 的默认 `extractRenderState` 只做一件事——遍历 `renderables` 逐个调
>    `Renderable.extractRenderState`。** 所以覆写之后**必须调 `super.extractRenderState(...)`**，
>    否则自己用 `addRenderableWidget` 加的按钮一个都不显示；而且**不报错、不崩**，
>    表现只是"界面里空空的没有按钮"，光看日志绝对查不出来。
> 2. 背景暗化/模糊也没人帮你画了：`extractBackground(gfx, mouseX, mouseY, partialTick)` 是 public
>    可以直接调；懒得管就自己 `gfx.fill(0, 0, this.width, this.height, 0xB4000000)`。
>
> 子控件仍是老写法：`Button.builder(Component, Button.OnPress).bounds(x,y,w,h).build()` +
> `addRenderableWidget(...)`（`Button.OnPress` 是 `void onPress(Button)`）；自定义控件改覆写
> `AbstractWidget#extractWidgetRenderState(GuiGraphicsExtractor,int,int,float)`；
> 鼠标事件签名变了：`mouseClicked(MouseButtonEvent, boolean)`（新 record，取 `event.x()/y()/button()`）。
> 完整面板骨架（含按键、经验结算、数据附件）见 `代码片段.md` §19。

> ⚠️ **26.1 实战补充（2026-09 小地图 mod 实测）**：`net.minecraft.client.gui.GuiGraphics`
> 这个类在 26.1 **已经不存在**（只剩 `Gui` / `GuiGraphicsExtractor` / `Font`），
> `RenderGuiEvent#getGuiGraphics()` 返回的是 **`GuiGraphicsExtractor`**——只有
> `fill` / `outline` / `text` / `scissor` / `pose()`，没有带 UV 的 blit。
> 自定义 HUD 要走 NeoForge 的 **`RegisterGuiLayersEvent` + `GuiLayer`**（mod bus 客户端事件，
> `registerAboveAll(id, layer)` 画在所有原版层之上）；⛔ **画贴图一律走
> `gfx.blit(GpuTextureView, GpuSampler, x0, y0, x1, y1, u0, u1, v0, v1)`，千万别用
> `gfx.fill(RenderPipelines.GUI_TEXTURED, TextureSetup.singleTexture(...), ...)`** ——
> 后者生成的是 `ColoredRectangleRenderState`（不写 UV0），配需要 UV 的管线进游戏画第一帧就抛
> `Missing elements in vertex: UV0`；sampler 自己从 `RenderSystem.getSamplerCache()` 取。
> 完整代码与踩坑记录见 `代码片段.md` §17.2 / §17.3。
>
> 同理，**26.1 的 Screen 丢掉了 `render(GuiGraphics,…)`**：自定义面板要覆写
> `extractRenderState(GuiGraphicsExtractor, int mouseX, int mouseY, float partialTick)`，
> 而且**必须调 `super`**（默认实现负责遍历 `renderables` 画所有按钮），否则按钮全都不显示、
> 且不报任何错。面板骨架见 `代码片段.md` §19。
>
> 另外 26.1 编译期**拿不到 `FMLEnvironment.dist`**（类在、字段没了），纯客户端 mod 判断端用
> `Class.forName("net.minecraft.client.Minecraft")` 是否成功。

// BlockPos -> ChunkPos

ChunkPos.asLong(blockPos) → ChunkPos.pack(blockPos)

**⑤ 注册写法变化（官方 MDK 实测对照）**

```java
// 1.21.1：传 Properties 实例
public static final DeferredBlock<Block> EXAMPLE_BLOCK =
    BLOCKS.registerSimpleBlock("example_block", BlockBehaviour.Properties.of().mapColor(MapColor.STONE));
public static final DeferredItem<Item> EXAMPLE_ITEM =
    ITEMS.registerSimpleItem("example_item", new Item.Properties().food(...));

// 26.1：改传 lambda（函数式配置）
public static final DeferredBlock<Block> EXAMPLE_BLOCK =
    BLOCKS.registerSimpleBlock("example_block", p -> p.mapColor(MapColor.STONE));
public static final DeferredItem<Item> EXAMPLE_ITEM =
    ITEMS.registerSimpleItem("example_item", p -> p.food(...));
```

其余（`DeferredRegister.Blocks`/`.Items`、`DeferredBlock`/`DeferredItem`/`DeferredHolder`、
构造函数注入 `IEventBus` + `ModContainer`、`BuildCreativeModeTabContentsEvent`）在 1.21.1 与 26.1 **保持一致**。

**⑥ 工具/盔甲具体类删除（1.21.5 起，26.x 沿用）**

`SwordItem`/`PickaxeItem`/`AxeItem`/`ShovelItem`/`HoeItem`/`ArmorItem` 等**具体基类已删除**，不能 `extends SwordItem`。改用 `Item.Properties` 的工厂方法 + record 材料（`ToolMaterial`/`ArmorMaterial` 不再是注册表项，直接 `new`）：

```java
// 工具：p.sword/pickaxe/axe/shovel/hoe(ToolMaterial)
ITEMS.register("my_pickaxe", p -> p.pickaxe(MY_TOOL));
// 盔甲：p.humanoidArmor(ArmorMaterial, ArmorType)
ITEMS.register("my_helmet", p -> p.humanoidArmor(MY_ARMOR, ArmorType.HELMET));
```

配套资源注意：装备层 JSON 在 `assets/<ns>/equipment/`（不是 data/），贴图在 `assets/<ns>/textures/entity/equipment/humanoid/`。完整写法+数值对照见 `代码片段.md` §13。

**纯穿戴物品（无护甲值）走另一条路**：`ArmorItem` 没了，但也没有「非盔甲的一步穿戴工厂」。眼镜/饰品/披风这类不提供护甲值的可穿戴物品，用 `equippable(EquipmentSlot)` 数据组件 + **普通 `Item`**：

```java
ITEMS.registerItem("my_glasses", Item::new,
    p -> p.stacksTo(1).equippable(EquipmentSlot.HEAD));
```
判定：**要不要护甲值**？要 → `p.humanoidArmor(...)`；不要 → `.equippable(slot)`。两者别混。

**⑧ 26.1 命令与方块状态 API 变更（连锁挖矿 mod 实测）**

| 变更 | 26.1 前 | 26.1 | 影响 |
|---|---|---|---|
| 命令权限判定 | `CommandSourceStack#hasPermission(int)` | **方法已删除**，改用 `source.permissions().hasPermission(Permissions.COMMANDS_GAMEMASTER)` | 编译期报「找不到符号 hasPermission(int)」 |

// 旧：.requires(source -> source.hasPermission(2))
// 新：
.requires(source -> source.permissions().hasPermission(Permissions.COMMANDS_GAMEMASTER))

**⑨ 🔴 26.1.2 破坏事件重构：`BlockEvent.BreakEvent` → `BreakBlockEvent`（实测）**

**26.1.2 是一次真正的破坏性重构**，26.1.0.x 上编译的 mod 在 26.1.2 上直接编译失败：

| | 26.1.0.19-beta | 26.1.2.109 |
|---|---|---|
| 全限定名 | `net.neoforged.neoforge.event.level.BlockEvent$BreakEvent` | `net.neoforged.neoforge.event.level.block.BreakBlockEvent` |
| 形态 | `BlockEvent` 的**内部类** | **独立顶层类**，继承 `BlockEvent` |
| 包 | `event.level` | **`event.level.block`**（新包） |

NeoForge 把 `BlockEvent` 家族按方块/其他拆分了：`event.level.block.*` 下现在有
`BreakBlockEvent` / `CropGrowEvent` / `CreateFluidSourceEvent`，
而 `event.level.BlockEvent` 只留作公共父类（`getLevel()` / `getPos()` / `getState()` 仍在这里）。

**方法签名基本不变**（只是换名字）：

```java
// 26.1.0.x
import net.neoforged.neoforge.event.level.BlockEvent.BreakEvent;
public void onBreak(BreakEvent event) { ... }
new BreakEvent(level, pos, state, player);

// 26.1.2+
import net.neoforged.neoforge.event.level.block.BreakBlockEvent;
public void onBreak(BreakBlockEvent event) { ... }
new BreakBlockEvent(level, pos, state, player);
```

| 方法 | 26.1.0.19 | 26.1.2.109 |
|---|---|---|
| 构造 | `(Level, BlockPos, BlockState, Player)` | 同 |
| `getPlayer()` | ✅ | ✅ |
| `setCanceled(boolean)` | ✅ | ✅ |
| `shouldNotifyClient()` / `setNotifyClient(boolean)` | — | **新增** |

**🔴 由此得出的通用铁律：部署到目标实例前，必须按目标实例的版本重新编译验证。**

踩坑场景很常见：开发脚手架的默认版本（如 26.1.0.19-beta）比用户实例（26.1.2.109）
**旧**，编译轻松通过，但产出的 jar 到实例上会因为类不存在而加载失败。
**编译通过 ≠ 能部署**。正确流程：

```properties
# gradle.properties —— 先对齐成目标实例的版本，再编译
minecraft_version=26.1.2
neo_version=26.1.2.109
```

实例的实际版本可以从 PCL2 的 `versions/<实例名>/PCL/Setup.ini` 直接读到：

```ini
Info:正式版 26.1.2, NeoForge 26.1.2.109
VersionNeoForge:26.1.2.109
```

改完版本重新 `build`，编译错误就是最好的兼容性报告 —— 本次正是靠它当场发现事件改名。

世界渲染逐帧画线的完整写法（含顶点四要素铁律）见 `代码片段.md` §10「世界渲染：逐帧画线」。

### 9.4 Fabric 26.x 工具链（实测自 fabric-example-mod@26.2）

`gradle.properties` 实际值：
```properties
minecraft_version=26.2
loader_version=0.19.3
loom_version=1.17-SNAPSHOT
fabric_api_version=0.158.0+26.2
version=1.0.0
group=com.example
```
- 注意：**没有 `yarn_mappings` 行**（26.x 无 mappings）
- `org.gradle.configuration-cache=false`（IntelliJ 兼容问题，官方模板如此设置）

`build.gradle` 关键写法：
```gradle
plugins {
    id 'net.fabricmc.fabric-loom' version "${loom_version}"   // 注意：不是 'fabric-loom'
    id 'maven-publish'
}
loom {
    splitEnvironmentSourceSets()
    mods { "modid" { sourceSet sourceSets.main; sourceSet sourceSets.client } }
}
dependencies {
    minecraft "com.mojang:minecraft:${project.minecraft_version}"
    implementation "net.fabricmc:fabric-loader:${project.loader_version}"   // 不是 modImplementation
    implementation "net.fabricmc.fabric-api:fabric-api:${project.fabric_api_version}"
}
tasks.withType(JavaCompile).configureEach { it.options.release = 25 }
jar { from("LICENSE") { rename { "${it}_$projectName"} } }   // 是 jar 不是 remapJar
```

`fabric.mod.json` 关键点：
- `depends` 里用 **`fabric-api`**（不是旧的 `fabric`；`fabric` 这个 mod id 已移除）
- `minecraft: "~26.2"`、`java: ">=25"`、`fabricloader: ">=0.19.3"`
- mixins 分主端与 client 端：`"modid.mixins.json"` + `{ "config": "modid.client.mixins.json", "environment": "client" }`

mixins.json（26.x）：
```json
{
  "required": true,
  "package": "com.example.mixin",
  "compatibilityLevel": "JAVA_25",
  "mixins": ["ExampleMixin"],
  "injectors": { "defaultRequire": 1 },
  "overwrites": { "requireAnnotations": true }
}
```
客户端 mixin 配置放在 **`src/client/resources/modid.client.mixins.json`**，内部用 `"client": ["ExampleClientMixin"]`。

**其他 26.x Fabric 变更**：
- `.accesswidener` → **`.classtweaker`**，头部写 `classTweaker v2 official`（旧版是 `accessWidener vX named`）
- Fabric API 改名对齐 Mojang 官方名：`ItemGroupEvents` → `CreativeModeTabEvents`
- 移除：`fabric-convention-tags-v1`、`fabric-loot-api-v2`、`HudRenderCallback`（改用 `HudElementRegistry`）
- 新增：`DimensionEvents.MODIFY_ATTRIBUTES`、`BlockEvents#USE_ITEM_ON`/`USE_WITHOUT_ITEM`、`ItemEvents#USE_ON`/`USE`、`BlockColorRegistry`、`GameRuleBuilder` + `GameRuleEvents`
- 数据生成：`fabricApi { configureDataGeneration { client = true } }`，provider 用 `FabricDataOutput#createPack()`
- IntelliJ 需 **2025.3+** 才能正常处理 mixin
- 26.2 起渲染后端可选 **Vulkan**，OpenGL 计划移除 → 用原始 OpenGL 调用的代码需迁到 Blaze3D API
- 官方源码浏览工具：https://mcsrc.dev/

### 9.5 迁移工作流建议（NeoForge 官方推荐）

同时保留两个工作区：一个能编译的 1.21.11（或 1.21.1）工作区 + 一个进行中的 26.1 工作区。
1. 找到 26.1 里编译不过的调用 → 2. 在 1.21.11 工作区找到同一调用 → 3. 右键跳到一个 vanilla 用法（需附加 MC 源码，搜索范围设为 All Places）→ 4. 看 26.1 里 vanilla 怎么改的 → 5. 照着改自己的代码。

更多变更见官方 primer：https://github.com/neoforged/.github/blob/main/primers/26.1/index.md

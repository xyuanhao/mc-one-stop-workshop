# 空岛 / 虚空 / 单方块开局整合包（1.20.1 实测）

> 场景：要做一个「虚空世界 + 自定义开局岛」的整合包（空岛、单方块、one block）。
> **不需要写 mod** —— 用 Skyblock Builder 的配置就能精确控制岛的每一个方块。
> 实测环境：MC 1.20.1 Forge 47.4.23，SkyblockBuilder 1.20.1-5.1.33 + LibX。

---

## 0. 先定「无中生有」用哪个 mod（最大的坑在这里）

| mod | 1.20.1 情况 | 结论 |
|---|---|---|
| **Ex Nihilo: Sequentia**（exnihilosequentia） | **5.0.0 起只发 NeoForge**（作者原文：*Beginning with 5.0.0 (1.20.1), ENS will only support NeoForge*）。Modrinth 上 1.20.1 只有 1 个 forge 文件（2024-01 的 build.6），后续 6 个都是 neoforge | Forge 包**别用**。它唯一的依赖 NovaCore 在 1.20.1 也只有 neoforge |
| **Ex Deorum**（ex-deorum） | Ex Nihilo 官方精神续作（作者原话：*a port of the 1.7 SkyBlock companion mod Ex Nihilo*）。1.20.1 有 **53 个版本、2026-07 还在更**，forge+neoforge 双标，**0 mandatory 依赖** | ✅ **Forge 包选它** |

**Ex Deorum 白送的三件事**（省掉大量配置工作）：
1. **自带 SkyBlock 世界类型**（`exdeorum:void`）—— 不装 Skyblock Builder 也能开局
2. **开局给玩家木制浇水壶 + 火把**（可配置）
3. **全部配方都在数据包** `data/exdeorum/recipes/{sieve,hammer,barrel_*,crucible_*}/…` —— 改配方不用写 mod

> ⚠️ Ex Deorum 的 coremod 会**改写 `server.properties` 的默认世界类型**（日志：`Successfully patched server.properties to use void world type by default`）。
> 想阻止：`config/exdeorum-common.toml` → `set_void_world_as_default = false`。
> 如果 server.properties 里已经显式写了别的 level-type，它不会覆盖，但世界创建界面的**默认选项**会被它抢走。

配套：**Ex Compressum**（excompressum）1.20.1 明确支持 Ex Deorum（描述里点名），提供压缩锤/重型筛/自动筛锤/诱饵。依赖 Balm。

## 1. Skyblock Builder：把岛做成「一个草方块」

### 1.1 关键认知：模板 = 原版结构文件

岛模板就是一个**原版 StructureTemplate 的 `.nbt`**（结构方块导出格式），放在：

```
config/skyblockbuilder/templates/<名字>.nbt
```

**可以离线直接造**，不用进游戏摆结构方块（本包就是 Python 手写 NBT 生成的）。1.20.1 的结构文件格式：

```
TAG_Compound("") {
  DataVersion: 3465            # 1.20.1
  size:  [1, 1, 1]             # TAG_List of TAG_Int
  palette: [ {Name: "minecraft:grass_block"} ]
  blocks:  [ {pos: [0,0,0], state: 0} ]     # pos 也是 List<Int>，不是 IntArray
  entities: []
}
```

要点：
- **根必须是 `TAG_Compound` + 空名字**（漏了这层会 `assert t == TAG_COMPOUND` 失败）
- `pos` / `size` 是 `TAG_List<TAG_Int>`，不是 `TAG_Int_Array`
- `state` 是 palette 下标，单一方块写 `0`
- 结构原点 = 结构里的 `[0,0,0]` 那一格

### 1.2 `templates.json5`

```json5
{
  "defaultOffset": 0,        // 岛在世界里的 x/z 偏移
  "spawn": null,             // 出生专用模板名；null = 用 templates 列表第一项
  "spawns": {                // 出生点，坐标「相对模板原点」
    "default": {
      "west": [], "east": [],
      "south": [ [0, 1, 0] ],  // ← 单草方块：取它正上方一格
      "north": []
    }
  },
  "spreads":           { "default": [] },
  "surroundingBlocks": { "default": [] },
  "templates": [
    { "name": "单块空岛", "desc": "一个草方块，别无他物",
      "file": "one_grass_block.nbt", "spawns": "default",
      "surroundingBlocks": "default", "spreads": "default" }
  ]
}
```

- `spawns` 的四个方向键**都要在**（空数组即可），`templates[0]` 即默认模板
- 模板 `name` 可以直接写中文（控制台日志会显示乱码，那是终端编码问题，不是配置错）

### 1.3 `spawn.json5` —— **`Height.range.bottom` 同时决定岛的高度和出生高度**

```json5
{
  "dimension": "minecraft:overworld",
  "Height": {
    "offset": 0,
    "range": { "bottom": 65, "top": 319 },
    "spawnType": "set"        // set = 固定用 bottom 当高度
  },
  "radius": 50
}
```

实测（2026-09-17）：`bottom: 64` → 草方块生成在 y=64；改成 `bottom: 65` → 草方块在 **y=65**，队伍岛同步落到 `(0, 65, 0)`。
所以**改这一个值就能整体升降岛**，不用碰模板。

有效出生点的定义 = **固体块上方两格空气**（`#skyblockbuilder:additional_valid_spawns` 里额外放行了树叶和水）。
`radius: 50` 是「给定 spawn 点无效时在其周围 50 格内找替代点」的兜底 —— 但别依赖它，直接把 spawn 点配对。

### 1.4 `starter_inventory.json5` —— 开局给物品（空岛的救命配置）

```json5
{ "items": [
    { "item": "minecraft:oak_sapling", "count": 2 },
    { "item": "exdeorum:wooden_watering_can", "count": 1 },
    { "item": "minecraft:torch", "count": 4, "Slot": "offhand" }
] }
```

`Slot` 可选（`mainhand`/`offhand`/`head`/`chest`/`legs`/`feet`）。

配套 `inventory.json5`：

```json5
{ "clearInv": false, "dropItems": true, "initialInventoryType": "spawn" }
```
`initialInventoryType` 默认是 `team`，**单人包里要改成 `spawn`** 才会在首次进世界时发。

> 🔴 **空岛包必修**：Ex Nihilo 系的木头是硬通货（筛子/木桶/锤子全要木头），
> 而「单个草方块」开局**没有任何木头来源** → 不给树苗 = 死局。
> 所以「单方块开局」在配置上必然要配一份 starter inventory（或任务书首个奖励）。

### 1.5 让 Skyblock 成为新建世界的默认类型

Skyblock Builder 只在「更多世界选项」里加一个选项，不会自动选中。要默认选中装独立小 mod：

- **Default World Type**（Modrinth slug `defaultworldtype`，1.20.1 只有 beta 版 1.20.1-4.0.5，纯客户端）
- 配置文件：`config/defaultworldtype/client-config.toml`

```toml
world-preset = "skyblockbuilder:skyblock"
```

（字段名是从 jar 的 `ClientConfig` 反查的：`worldTypeName` → key `world-preset`；另有 `allowed-world-types` 列表。）

服务端用 `server.properties`：`level-type=skyblockbuilder\:skyblock`（注意 Java Properties 的冒号转义）。

## 2. 怎么证「岛真的是这样」—— 起服务端取证

不要靠"配置看起来对"。起一个专用服务端（`java -jar forge-installer.jar --installServer`），把配置拷进 `_server/config/`，删掉 `world/` 重开，然后：

### ① 读启动日志（最直接的证据）

```
[de.me.sk.SkyblockBuilder/]: Successfully generated spawn.
[de.me.sk.SkyblockBuilder/]: Created team Spawn (00000000-...) at BlockPos{x=0, y=65, z=0} with template 单块空岛
```

`BlockPos` 就是队伍的岛位置。**这行同时证明了模板被读到、岛的位置对、出生点被算出来。**

FTB 任务书的验证也在同一份日志：`Loaded 2 chapter groups, 5 chapters, 53 quests, 0 reward tables`。

### ② 离线扫存档

```bash
python 扫区域文件.py _server/world minecraft:grass_block minecraft:oak_log minecraft:chest
python 探地表高度.py --mca _server/world/region
```

空岛包期望的结果长这样：

```
共扫描 1953 个已生成区块
  minecraft:grass_block: 命中 1 个区块 → [(0, 0)]
  minecraft:oak_log: 命中 0 个区块        ← 确认没有多余的树/平台
离线档位分布：出现 2 个高度档位
  ★ y=-65  136447 列 100%    ← 虚空
       y=65       1 列        ← 唯一的那格
```

`探地表高度.py` 的 `raw + min_y - 1` 就是方块实际 y，用它确认岛落在期望高度。

### ③ RCON 点验出生点有效性

`execute if block <x> <y> <z> <方块> run time query daytime`（命中回 `The time is …`，未命中回 `Test failed`）——
比 `data get block` 可靠（后者对无 block entity 的方块返回空，成功失败分不出来）。

要验的是「spawn 点 + 它上面一格都是空气，下面一格是固体」：

```
execute if block 0 65 0 minecraft:grass_block run time query daytime   → 命中
execute if block 0 66 0 minecraft:air            run time query daytime   → 命中
execute if block 0 67 0 minecraft:air            run time query daytime   → 命中
```

## 3. 坑清单（都踩过）

| 现象 | 真因 | 处置 |
|---|---|---|
| 1.20.1 Forge 包装不上 Ex Nihilo: Sequentia | ENS 5.0.0 起只发 NeoForge | 换 Ex Deorum，或整体改用 NeoForge |
| `server.properties` 的 level-type 被莫名改掉 | Ex Deorum coremod 抢默认世界类型 | `set_void_world_as_default = false` |
| 岛生成在 y=0 附近 / 玩家出生在方块里 | 没设 `Height.range.bottom` | 设成「岛顶面 + 1」的高度，`spawnType: "set"` |
| 开局完全没法玩 | 空岛没有木头，又没给树苗 | `starter_inventory.json5` 至少给 1-2 个树苗 |
| 开局物品没发 | `inventory.json5` 的 `initialInventoryType` 默认 `team` | 改成 `spawn` |
| 玩家进不去末地 | 虚空世界不生成要塞 | 任务书别写"去末地"；或加能造传送门的 mod |
| 控制台模板名是乱码 | Windows 控制台 GBK 打印 UTF-8 | 不是 bug，别改配置 |
| 任务书 `dependencies` 全部报断链 | 生成器的 id 分配函数**不是幂等**的（同一 key 二次调用因去重表而返回不同 id） | 生成器里给 `key → id` 加缓存字典，保证同 key 同 id |

## 4. 任务书物品可获得性核查（空岛最容易翻车的一步）

> 2026-09-17 实测踩到：任务书里 55 个 item 任务，**有 1 个物品根本没有配方**（Ex Compressum 的 `evolved_orechid`，
> 那东西只在装了 Botania 时才注册配方），另有 4 个任务因为前置物品「筛子筛不出来」而实际上卡死。
> **id 拼写对着呢 —— 但玩家做不出来。**

### 4.1 两步核查法

**第一步：物品 id 存不存在**（对照 jar 的 `assets/<ns>/models/item/*.json` + `blockstates/*.json` + `lang` 的 `item.`/`block.` 键）。

**第二步（关键，别省）：这个物品能不能产出**。建「可产出集合」时**必须递归进 `forge:conditional` 内层**
——Ex Deorum 有 **729 个**配方包在 conditional 里（按所装 mod 条件启用），只读外层会得到"没有配方"的假结论。

```python
def collect_results(d, out):
    if d.get("type") == "forge:conditional":
        for e in d.get("recipes", []):
            collect_results(e.get("recipe", {}), out)   # ← 少了这层就全错
        return
    r = d.get("result")
    if isinstance(r, str): out.add(r)
    elif isinstance(r, dict):
        for k in ("item", "id"):
            if isinstance(r.get(k), str): out.add(r[k])
```

对账口径：任务书里 `item: { Count: n, id: "..." }` 出现的每个非 `minecraft:` 物品，都要能在集合里找到。
`minecraft:` 命名空间的原版配方不在 mod jar 里，会全部报"无配方"——那是假阳性，单独列出人工过一遍即可。

### 4.2 空岛特有陷阱表（Ex Deorum 1.20.1 实测）

| 物品 | 能不能筛出来 | 真实来源 | 后果 |
|---|---|---|---|
| **皮革 leather** | ❌ 筛不出来 | **只能靠动物**（Ex Compressum 诱饵 → 牛） | 背包 / 书 / 书架 / upgrade_base 全部依赖它 |
| **黏液球 slime_ball** | ❌ 筛不出来 | 牛奶 → 木桶 → **黏液块** → 拆 9 个 | 黏性活塞 → 背包拾取升级卡死 |
| **墨囊 ink_sac** | ❌ 筛不出来 | 鱿鱼（`squid_bait` 要 **2 条鱼**） | 黑色染色玻璃 → Cooking for Blockheads 烤箱做不出来 |
| **鱼 fish** | ❌ 筛不出来 | 只能「坩埚攒水池 + 钓竿」 | 连带 squid_bait 整条链断掉 |
| **钻石 diamond** | ✅ 但**要筛「粉碎深板岩」** | 泥土×9→压缩泥土→筛出深板岩石子→×4 圆石深板岩→烧→×9 压缩→**压缩锤**砸碎→筛 | 需要先有压缩锤，属于中期目标 |
| 甘蔗 / 仙人掌 / 竹子 / 海带 / 可可豆(否) / 骨 / 荧石粉 / 红石 / 青金石 / 绿宝石 / 石英 / 烈焰粉 / 末影珍珠 | ✅ 能筛 | 具体筛料见 jar 的 `data/exdeorum/recipes/sieve/` | — |

**结论**：空岛任务书的**章节顺序必须让「诱饵」早于任何依赖动物产物的任务**。
本包原本把诱饵放在第 4 章，而第 3 章的背包（皮革）、厨房（皮革/墨囊）全在第 4 章之前 → 整章卡死。
修法：把「先解决动物」提为第 3 章的第一个任务，把门槛过高的（料理台要 2 钻石、烤箱要墨囊）标 `optional: true`。

### 4.3 门槛顺延原则

写任务书时对每个 item 任务问一句「**这一刻玩家手上真有这个东西的来源吗**」。
两个高频误判：
- 配方链**通**但**很长**（钻石要 7 步）→ 不该出现在第 2-3 章
- 配方链**不通**（皮革/墨囊）→ 要么把来源章节提前，要么标 optional

### 4.4 自动化机器的能量陷阱

Ex Compressum 的 `AutoSieve` / `AutoHammer` / `AutoCompressor` / `AutoHeavySieve` / `AutoCompressedHammer`
**全部依赖 Balm 的 EnergyStorage（FE）**。纯虚空包如果没装发电 mod，这些机器做出来就是废铁。

两个选择：
1. **改配置免能量**（推荐给轻量包）—— `config/excompressum-common.toml`：
   `autoSieveEnergy` / `autoHammerEnergy` / `autoCompressorEnergy` / `autoHeavySieveEnergy` / `autoCompressedHammerEnergy` **全设 0**
   （逻辑上 `drainEnergy(0)` 恒成功），然后在任务书 / README 里**如实告诉玩家**你改了这一项。
2. 加发电 mod（Powah / Create / Generator Galore 之类）—— 但会让「极简空岛」的定位跑偏。

同样的判断也适用于**任何**依赖 FE 的自动化 mod：**先查它吃什么能量，再决定任务书能不能写"全自动"。**

## 5. 交付前检查清单

```
[ ] 起服务端，日志出现 `Successfully generated spawn` + `Created team … at BlockPos{…}`
[ ] 日志里 BlockPos 的 y == 期望的岛高度
[ ] 扫区域文件：只有目标方块，数量正确（单方块包应该是「命中 1 个区块」）
[ ] 探地表高度：绝大多数列在虚空、少数列在目标高度
[ ] RCON 验 spawn 点上下三格的方块类型
[ ] starter_inventory 的每个物品 id 都从 jar 的 lang / models 里核过（别猜）
[ ] 打包后解压回检：mods/ + config/ + README 都在，模拟实例跑一次 整合包验证.py 四项全过
[ ] ★ 任务书里每个非原版 item 任务都过了「可获得性核查」（**递归 forge:conditional 内层**），
      没有「id 拼得对、但玩家做不出来」的任务
[ ] ★ 依赖动物产物的任务（皮革 / 黏液球 / 墨囊 / 鱼）排在「诱饵」任务**之后**
[ ] ★ 依赖 FE 的自动化机器：要么包里有电源，要么已在配置里设为零能耗**并如实告知玩家**
[ ] ★ 配方链很长（≥5 步）的物品没有出现在早期章节；门槛过高的任务已标 `optional: true`
[ ] ★ **按键冲突已排查**（不看不知道，查法见下）
[ ] ★ 高价值 mod 自带的 `lang/zh_cn.json` 能 `json.loads` 通过（有的 mod 自带文件就是坏的）

### 5.1 按键冲突排查（2026-09-17 实测：用户报「连锁挖矿没反应」）

**典型踩法**：Ore Excavation 的 `oreexcavation.key.excavate` 默认是 `~`，
而 FTB Quests 的 `key.ftbquests.quests` 默认也是 `~` —— 按下去打开的是任务书，连锁永远不触发。

查法：**从各 jar 的 `lang/en_us.json` 里把所有按键翻译键捞出来**（`.key.` 或 `key.` 前缀），
再和已知默认键对照：

```python
for jar in mods:
    lang = json.loads(z.read("assets/<ns>/lang/en_us.json"))
    hits = {k: v for k, v in lang.items() if ".key." in k or k.startswith("key.")}
```

修法：在 `实例/options.txt` 里**显式写按键绑定**，格式是 `key_<按键翻译键>:<键名>`：

```
key_key.oreexcavation.key.excavate:key.keyboard.v
key_key.sophisticatedbackpacks.open_backpack:key.keyboard.n
```

已知容易撞的组合：`~`（Ore Excavation × FTB Quests）、
`R`（JEI 看配方 × Inventory Profiles Next 一键整理）、
`B`（Xaero 世界地图 × Sophisticated Backpacks 开背包）。

> ⚠️ **别把"功能键"和"默认就一直生效的键"一起绑**：例如不要显式绑 `key.jade.show_overlay`
> （它默认占左 Alt「看详情」），显式写反而会抢掉玩家习惯的键。

**mod 自带语言文件坏**也是同类问题：`oreexcavation-1.13.170.jar` 的 `zh_cn.json` 尾随逗号
导致 Gson 解析失败 → 中文翻译整块加载不出来。打包前对所有高价值 mod 的 lang 文件跑一次 `json.loads`，
坏的就重写（顺便补全比 en_us 缺的键）。
```

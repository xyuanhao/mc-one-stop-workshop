# 方块光照与透光（1.20.1 反汇编全链，2026-10-14 实测）

> 场景：想让**实心的**方块透天光 —— 像玻璃那样；或做「外壳当太阳」（晶壁球壳透光、内部有昼夜）。
> 痛点：改了 `getLightBlock()` 却不生效，游戏**零报错**，只是黑着。

## 1. 天光穿透的三件套（缺一不可）

| # | 条件 | 写在哪 |
|---|---|---|
| 1 | `.noOcclusion()` | 方块 `Properties` —— **真正的开关，最容易被误删** |
| 2 | `getLightBlock() → 0` | 覆盖 `BlockBehaviour#getLightBlock` |
| 3 | `propagatesSkylightDown() → true` | 覆盖 |

```java
// 属性
BlockBehaviour.Properties.of().noOcclusion().lightLevel(s -> 12) /* ... */;

// 覆盖（1.20.1 官方映射标了 @Deprecated 但没有替代 API → 必须把 @SuppressWarnings 挂上）
@Override
@SuppressWarnings("deprecation")
public int getLightBlock(BlockState state, BlockGetter level, BlockPos pos) {
    return 0;
}

@Override
public boolean propagatesSkylightDown(BlockState state, BlockGetter level, BlockPos pos) {
    return true;
}
```

## 2. 为什么是 `noOcclusion()` 说了算（完整判据链）

```
ChunkSkyLightSources.isEdgeOccluded(level, pos1, state1, pos2, state2)
├─ ① if (state2.getLightBlock(level, pos2) != 0) return true;        // 条件 2 过这关
└─ ② return Shapes.faceShapeOccludes(
        LightEngine.getOcclusionShape(level, pos1, state1, DOWN),
        LightEngine.getOcclusionShape(level, pos2, state2, UP));
      └─ LightEngine.getOcclusionShape:
           isEmptyShape(state) ? Shapes.empty() : state.getFaceOcclusionShape(level, pos, dir)
           └─ LightEngine.isEmptyShape(state):
                !state.canOcclude() || !state.useShapeForLightOcclusion()
                └─ BlockStateBase.canOcclude() → 读字段 ← 构造器 = properties.canOcclude
                     └─ Properties.noOcclusion() 只做一件事：canOcclude = false
```

要点：

- **有完整碰撞箱的方块，`getFaceOcclusionShape` 是完整立方体**；`faceShapeOccludes`
  只要任一形状是完整立方体就返回 true —— 即 `canOcclude()==true` 时第 ② 关**必判遮挡**。
- 是 `noOcclusion()` 把 `isEmptyShape` 短路成 true、让第 ② 关**直接返回空形状**，才放行的。
- `Properties.noOcclusion()`（SRG `m_60955_`）**只设 `canOcclude` 一个字段**；
  对比 `noCollission()`（SRG `m_60910_`）设 `hasCollision + canOcclude` 两个 —— 别搞混。
- 🔵 **同一族里还有第二个「只关一个字段」的入口：`Properties.forceSolidOff()`（SRG `m_280574_`）只关 `legacySolid`**
  —— 它管的是**另一个完全独立的守门条件**：出生点搜索用的高度图 `MOTION_BLOCKING` 是否把这个方块算作障碍
  （判据链 `blocksMotion() → isSolid() → calculateSolid() → forceSolidOff`）。
  透光读 `canOcclude`，出生点读 `legacySolid`，两者互不影响 ——
  「碰撞箱留着、透光留着、但不算 solid」是 `forceSolidOff()` 独有的效果，
  用 `noCollission()` 硬凑会连带关掉碰撞与天光。完整推导见 `26.x-自定义世界生成器.md` §8.3。
- 🔴 **删掉 `noOcclusion()`：天光全断，但游戏零报错**（只表现为内部变黑）。
  「这是实心墙，要 noOcclusion 干嘛」的直觉是**错的**。
- 🔴 **不必也不要把 `getShape()` 改薄来透光**：改薄 = 物理碰撞没了（玩家掉穿方块）。
  完整碰撞箱与透光**不矛盾** —— 前者管物理，后者由 `canOcclude` 管。
- `getLightBlock` 的默认实现（反汇编）：
  `isSolidRender(level,pos) ? 15 : (propagatesSkylightDown(...) ? 0 : 1)` ——
  `noOcclusion()` 让 `isSolidRender` 为 false 后退到第二支，而那个默认值**不可见**
  （走 `BlockBehaviour$Properties` 构造时的缓存），所以条件 3 也显式覆盖，别猜。

## 3. 天光会被「烘焙」进区块存档（验证时的头号陷阱）

- 天光值随区块 NBT 落盘。**改代码不会重算旧区块** —— 老存档里读到的是旧衰减值。
- 实测：老存档球壳处天光逐格衰减 14/13/…；同一份代码**新生成**的列全程 15 零衰减。
  为此绕了一大圈（一度怀疑 `getBrightness` 被昼夜削、怀疑缓存读到旧值）。
- **规矩**：验证透光改动，必须开新世界 / 探索新区域；拿老存档读数下结论会得出相反的结论。

## 4. 读数工具与判据

- `level.getBrightness(LightLayer.SKY, pos)` = `LightEngine.getLayerListener(SKY).getLightValue(pos)`
  —— **预览层原值，不削昼夜**。读到 14 先查上方有没有遮挡，别怀疑昼夜。
- **判据三点一起看**（光强 0~15，单点分不清「透光成功」与「本来就亮/本来就黑」）：
  `外部敞亮处 == 内侧近壳处` 且 `内侧深处 < 外部`。
- **再加状态断言**（不依赖世界生成、老存档也稳）：
  `block.defaultBlockState().canOcclude() == false && state.getLightBlock(level, pos) == 0`
  —— 把「为什么能透光」固化成可执行判据；谁删了 `noOcclusion()` 会立刻变红。
- 逐格剖面诊断（本例 `/plane light <x> <z> <y0> <y1>`，打印 `天光/块光/方块id`）：
  定位壳高、老存档残留层、新旧区块差异，比出图快得多、不用重启服务端。

## 5. 查证方法（怎么自己复现这条链）

ForgeGradle 的缓存里有 SRG→官方名映射，配合 `javap -p -c` 反汇编即可对照：

```bash
# 1) 反汇编目标类（injected jar = 官方映射名 + SRG 成员名）
javap -p -c -cp forge-1.20.1-47.3.0-injected.jar \
    'net.minecraft.world.level.block.state.BlockBehaviour$Properties' > P.txt

# 2) 找「可疑方法」：无参、返回 Properties、设了 1~3 个 boolean 字段
grep -n "putfield.*Z" P.txt

# 3) 把字段/方法名翻译成官方名
grep "f_60895_" srg_to_official_1.20.1.tsrg     # f_60895_ → canOcclude
grep "m_60955_" srg_to_official_1.20.1.tsrg     # m_60955_ → noOcclusion
```

路径（本机实测）：

- `-injected.jar`：`<GRADLE_USER_HOME>/caches/forge_gradle/minecraft_user_repo/net/minecraftforge/forge/<ver>/forge-<ver>-injected.jar`
- 映射：`<GRADLE_USER_HOME>/caches/forge_gradle/minecraft_user_repo/de/oceanlabs/mcp/mcp_config/<ver>/srg_to_official_<ver>.tsrg`
- `javap` 用任意 JDK 25（如 `%APPDATA%\.minecraft\runtime\java-runtime-epsilon\bin\javap.exe`）即可，读 1.20.1 的 class 没问题。

# 26.x 游戏内自动化测试（让 AI 真的进游戏里跑一遍）

> 面向「**客户端侧的东西怎么自动验**」——HUD 画出来没有、界面点得动没有、按键绑上了没有、
> 模型是不是紫黑方块、第一帧会不会崩、**我的方块/道具被玩家真的右键时有没有反应**。
> 两层动作都要会：**①引擎层**（`cmd`/`state`/`shot` 上帝视角）与 **②玩家输入层**
> （`move`/`use`/`place`/`open_inventory`/`container` —— 真的按下去，见 §4.3 ②）。
> 全部结论都在 **MC 26.1 / NeoForge 26.1.0.19-beta / Windows 实机**上跑过。
> 配套：`scripts/游戏内测试.py`（驱动）、`scripts/游戏内注入.gradle`（注入）、
> `templates/测试代理-26.1/`（进程内代理 mod 源码）。

---

## 0. 一句话结论

**用「模组」当进程内代理，用「外部程序」当驱动与取证 —— 两者都要，但分工是死的：**

| 层 | 干什么 | 为什么非得是它 |
|---|---|---|
| **模组**（`测试代理-26.1`，Minecraft 进程内） | 进世界、执行命令、**走路/转向/右键/挖/放置/开背包/点槽位**、按键、开/点界面、截图、导出结构化状态、抓异常、退出 | 只有进程内才拿得到**结构化状态**和**确定性操作**。外部程序连"点一下某个按钮"都要抢前台焦点、按坐标猜 |
| **外部程序**（`游戏内测试.py`） | 构建代理、注入运行时、拉起客户端、按场景下发命令、收产物、断言、兜底关窗口 | 只有外部才方便**迭代**：改断言不用重编 Java，AI 直接写 Python 场景 |

⚠️ **反过来说清楚**：纯外部方案（AutoHotkey / pyautogui 那一类）在本机**做不到**
「不打扰用户地测试」—— 见 §2.3 的实测。

## 1. 这套东西能验什么（以前只能靠人眼盯着屏幕的那些）

| 以前 | 现在 |
|---|---|
| `runClient` 起来之后"看不见、摸不着"，只能交给用户实机验收 | 驱动自动进世界，命令 + 状态 + 截图全自动 |
| HUD/界面/模型渲染问题要等用户反馈 | **`shot` 截图给 AI 看**（AI 能读图），紫黑方块、错位、缺失一眼可见 |
| 「按键绑对没有」靠人按 | `key` 动作按翻译键触发，和玩家按键**同一条代码路径** |
| 「第一帧崩不崩」不知道 | 客户端异常全量落进报告（`客户端异常` 字段） |
| 「界面上按钮点了有没有反应」靠人 | `screen click` 按**翻译键**点按钮（不依赖坐标/分辨率），再读状态验证副作用 |
| 「我做的方块右键有没有反应」靠人 | ⭐ **`place` / `use` 走玩家右键那条路** —— 会真的进 mod 的 `useItemOn`（`/setblock` **不会**，它绕过了 mod 处理链） |
| 「走过去靠近、开背包、把物品塞进格子」靠人 | ⭐ **玩家输入层**：`move`（真按住方向键走）/ `open_inventory`（真按 E）/ `container click`（真点槽位）/ `hotbar` / `jump` / `mine` / `drop` —— 见 §4.3 ② |

{"id":9,"op":"shot","ok":true,"data":{"path":"…\\测试代理\\截图\\钻石块已放置.png"}}

## 2. 同类开源项目调研（2026-10）与取舍

### 2.1 全景表

| 项目 | 形态 | 能做什么 | 为什么不用它做「AI 进游戏测试」 |
|---|---|---|---|
| **Mojang GameTest**（`net.minecraft.gametest`）<br>`runGameTestServer` / `/test runall` | 原版框架，**服务端/世界逻辑** | 方块/实体/容器/红石断言，`helper.assertBlock(...)`、`runAfterDelay`，CI 里跑 | 它跑在**服务端**：没有玩家、没有画面、没有界面。HUD/按键/渲染完全覆盖不到 |
| **Fabric Client GameTest API**<br>`fabric-client-gametest-api-v1` | Fabric 官方（Fabric API 内）**客户端**测试框架 | `context.takeScreenshot()` / `assertScreenshotContains(template)` / `clickScreenButton(翻译键)` / `worldBuilder().create()` / `waitTicks()` / `TestInput` | **这是最接近的正解，但只在 Fabric 生态**。NeoForge 没有对应物 → 本 skill 的代理就是把它的**语义**（见 §2.4）在 NeoForge 侧重新实现一遍 |
| **Project Malmo / MineRL**（微软 / MineRL 团队） | **Forge mod + TCP/JSON + 外部 Python agent** | 观察（位置/背包/附近方块/**视频帧**）+ 动作（move/turn/use/attack）+ 任务 XML + 奖励 | 这是**架构先例**：证明了「mod 当桥、外部程序当驱动」是对的。但版本停在 1.11/1.16 一线，且为强化学习设计（要的是动作流，不是断言与截图取证） |
| **Mineflayer / `minecraft-mcp-server` 系列** | 纯外部，**协议 bot**（Node/JS） | 免 GPU、免 Java、可开几十个；MCP 包一层就能让大模型操作 | **看不到画面**（协议层没有渲染），也**装不了 mod**；协议支持停在 1.21.x，26.x 的年份版本号它还没跟。适合"在服务器里干活的机器人"，不适合"验证一个客户端 mod 画得对不对" |
| **MC-Runtime-Test + HeadlessMC**（headlesshq） | 外部启动器 + **一个轻量 mod**（进世界、等区块、几秒后退出） | CI 里做**启动冒烟**：能不能起来、能不能进世界、GameTest 跑不跑 | 它的定位就是"能起来就算过"。**明确声明不提供完整集成测试框架**；且本机是 Windows 真实桌面，不需要 Xvfb/LWJGL 打桩 |
| **Baritone / AltoClef** | 客户端 mod（寻路/自动化游玩） | 在真实客户端里自动走、挖、造 | 是"玩"，不是"测"：没有断言、没有截图取证、没有状态导出协议 |
| **Axiom / WorldEdit** | 客户端/服务端 mod | 游戏内编辑世界 | 编辑工具，不产生测试判据 |

### 2.2 两条路线为什么都不够

- **纯协议 bot（Mineflayer 系）**：验证面被砍掉一半 —— 客户端渲染、GUI、按键、模型贴图，
  这些恰恰是 mod 开发里最容易翻车（也是本 skill 老文档里"只能交给用户实机"）的部分。
  另外它**装不了被测 mod**：它连的是服务端，客户端那半边根本不存在。
- **纯外部 GUI 自动化（模拟键鼠 + 截图）**：见 §2.3，本机实测不可行。
- **只有 GameTest**：覆盖服务端逻辑很好，但**永远验不到画面**。

### 2.3 实测：为什么"纯外部"在本机不成立

| 事实 | 证据 |
|---|---|
| 外部**能看**：不用前台焦点、被别的窗口盖住也能抓 | `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)` 对 GLFW 窗口返回正常内容（实测采样 49/72 点非黑），抓到的是真实标题界面 |
| 外部**不能动**：GLFW 的键盘事件只在前台窗口产生 | 而窗口被抢到前台 = **用户正在看视频会被打断**。这不是"体验差"，是"没法人不在场时跑" |
| 坐标点击天然脆 | 界面按钮位置随分辨率/guiScale/语言变；翻译键才是稳定锚点 |

> **结论**：外部程序只能当**取证的兜底**（`游戏内测试.py shot` / `close` 两个子命令就是干这个的），
> 不能当主力驱动。主力驱动必须在进程内。

### 2.4 照搬了 Fabric 客户端 gametest 的哪些语义

Fabric 那套 API 是同类里设计最好的，本代理的动词表刻意对齐它（换 NeoForge 实现）：

| Fabric 客户端 gametest | 本代理 |
|---|---|
| `context.takeScreenshot(name)` | `{"op":"shot","name":...}` |
| `context.clickScreenButton(translationKey)` | `{"op":"screen","action":"click","value":"<翻译键>"}` |
| `context.waitTicks(n)` / `waitForScreen(Class)` | `{"op":"wait","ticks":n}` / `{"op":"wait_for","what":"screen",...}` |
| `context.worldBuilder().create()` | 启动配置 `world.mode=create`（走 `CreateWorldScreen.openFresh` + 点 `selectWorld.create`，**和它一模一样的做法**） |
| `context.assertScreenshotContains(template)` | 本代理只出图，比对交给外面的 AI/脚本（更灵活） |

## 3. 定稿架构

```
┌─ 外部（Python） ────────────────────┐   ┌─ Minecraft 进程内（代理 mod） ──────────┐
│ 游戏内测试.py                       │   │ 测试代理-26.1 / modid=mctestagent      │
│  ① 构建代理 jar（幂等）             │   │  · ClientTickEvent.Post 每 tick 推一次 │
│  ② init script 注入 runtimeOnly     │   │  · 动作**串行**执行（因果确定）        │
│  ③ 起 runClient（后台）             │   │  · 全程客户端线程，不跨线程碰状态      │
│  ④ 轮询 outbox → 打印/断言          │   │                                        │
│  ⑤ 收截图 / 异常 / 写报告           │   │                                        │
│  ⑥ 兜底：WM_CLOSE 优雅关窗          │   │                                        │
└─────────────┬───────────────────────┘   └───────────────┬────────────────────────┘
              │            文件协议（无端口 / 无防火墙）    │
              └─────────────────────────────────────────────┘
   run/测试代理/
     启动.json      ← 外部写：进哪个世界、开什么选项、兜底退出 tick
     inbox.jsonl    ← 外部追加：一行一条命令 {id, op, ...}
     outbox.jsonl   → 代理追加：一行一条结果 {id, op, ok, data/error}
     状态.json      → 代理每秒覆盖：心跳 / 当前界面 / 坐标 / 当前动作
     就绪.flag      → 代理写：客户端到可用界面了
     代理.log       → 代理写：UTF-8 诊断（**看这个，别看 gradle 日志**，见 §5.6）
     截图/*.png     → 代理写
```

### 3.1 为什么用「文件」而不是 socket / HTTP

| 方案 | 问题 |
|---|---|
| 监听端口 | Windows 会弹防火墙授权框（无人值守时卡死）；端口冲突；还要处理连接生命周期 |
| HTTP | 同上，且代理侧要多写一堆网络代码 |
| **文件** | 零依赖、零端口、零防火墙、崩了也能事后读；延迟一个 tick（50ms），对测试完全够 |

### 3.2 为什么"改动零侵入"能成立

代理 jar **不进被测试工程**，而是靠 Gradle 官方语义的 `runtimeOnly` 进开发运行期：

```
gradlew --init-script 游戏内注入.gradle -Dmctestagent.jars=<代理jar> runClient
```

实测日志（`Found valid mod file 游戏内测试代理-1.0.0.jar with {mctestagent}` 即注入成功）：

```
[mctestagent] 已注入 1 个 jar 到 GodsEnchant模组 的 runtimeOnly
Considering mod file candidate C:\…\mc-测试代理\26.1\build\libs\游戏内测试代理-1.0.0.jar
Found valid mod file 游戏内测试代理-1.0.0.jar with {mctestagent} mods - versions {1.0.0}
```

好处：**不改工程一个字节**，不插行、不备份、不留痕；配置缓存正确处理
（`configuration cache cannot be reused because init script … has been added`，之后正常复用）。

## 4. 怎么用

```bash
# 0) 先体检（JDK / 注入脚本 / 工程版本 / 代理 jar 在不在）
python scripts/游戏内测试.py doctor --project <工程目录>

# 1) 跑一份场景（工程会先自动构建代理，再用 init script 注入后起客户端）
python scripts/游戏内测试.py run --project <工程目录> --scenario my_scenario.py

# 2) 🔴 进游戏实测（交付门禁：不用写场景，跑完就有结论）
python scripts/游戏内测试.py smoke --project <工程目录>

# 3) 不进游戏也能用的两个兜底（不抢焦点）
python scripts/游戏内测试.py shot --out win.png     # 抓 Minecraft 窗口
python scripts/游戏内测试.py close                  # 优雅关掉客户端（= 点右上角 X）
```

### 4.0 🔴 `smoke`：进游戏实测门禁（交付前必过）

**它是 `run` 的退化版吗？不是** —— `run` 是「按场景验功能」，`smoke` 是「**有没有资格谈交付**」。
不用写场景脚本，一条命令出六条判据。规矩与定位表见 SKILL.md **§8**。

```bash
python scripts/游戏内测试.py smoke --project <工程>              # 默认 flat 世界，进世界后推进 100 tick
python scripts/游戏内测试.py smoke --project <工程> --preset normal --settle 200
python scripts/游戏内测试.py smoke --project <工程> --ready-line "Loaded 0 entity animations"   # 老版本通道
```

| 判据（26.x 代理通道） | 怎么判 |
|---|---|
| 客户端启动到主菜单 | `boot.ok` |
| 自动建世界并进入 | `boot.data` 的 `world` + `dimension` 都在 |
| 推进 N tick 后 `gameTime` 在涨 | 两次 `state` 的 `world.gameTime` 严格递增（卡加载 / §5.3 被暂停都会卡在这） |
| 玩家状态可读 | `state.player.pos` 有值 |
| 截图非黑屏 | 亮度均值 < 24 **且** 极差 < 8 判黑屏（全黑窗口是「进程活着、GL 没出图」，日志常常一声不吭） |
| 客户端日志无 ERROR / Exception | 扫 `run/logs/latest.log` 尾部 |

**老版本通道（1.20.1 / 1.21.x，无代理）**：起 `runClient` → 等窗口 → 等日志出现主菜单标志行
（默认 `Loaded 0 entity animations`，见 §5.1）→ 抓图非黑屏 → 日志无异常。
⚠️ **只到主菜单，不会自动进世界**，交付说明里必须写清。

**产物 / 退出码**：报告 `<run>/测试代理/冒烟报告.json`（逐条判据 ok + 客户端异常前 20 条）；
`0` = 全过 ｜ `1` = 有判据没过 ｜ `2` = 参数/环境问题。

> ⚠️ `smoke` 用的是**当前代码**：改了注册 / 渲染 / Mixin / 依赖之后要重跑，别拿"上次跑过"当证据。
> 另外它只证明"进得去、开头不崩"，内容行为仍按 §9 那张表用 `run` 分层验。

### 4.1 场景就是一段 Python（能读状态、能断言、能改主意）

```python
世界 = agent.进世界()                       # 启动阶段已按 --world-mode 进好世界
assert 世界["world"], 世界

agent.命令("time set day")                  # / 可以省
agent.命令("give @s minecraft:diamond_sword")
agent.等(10)                                # 等 10 tick（命令是异步的，见 §5.8）

st = agent.状态(radius=8)
assert st["player"]["creative"] is True
assert "minecraft:diamond_sword" in [s["item"] for s in st["inventory"]["slots"]]

agent.命令("setblock 5 100 5 minecraft:diamond_block")
agent.等(5)
assert agent.方块("5,100,5") == "minecraft:diamond_block"
assert agent.方块("5,101,5") == "minecraft:air"      # 负样本：判据不能恒真

agent.截图("钻石块已放置")                   # 产物给 AI 自己看
```

对象名是 `agent`（中文别名 `会话`）；方法中英双名（`agent.命令` == `agent.cmd`）。
`run` 的退出码：**0 场景全过 / 1 有失败 / 2 环境或参数问题** —— 能直接串进流水线。

### 4.2 它会往你的工程里写什么（先说清楚，免得看到 `git status` 吓一跳）

| 位置 | 内容 | 说明 |
|---|---|---|
| `<工程>/run/测试代理/` | 启动.json / inbox / outbox / 状态.json / 代理.log / 截图 / 报告.json | 全部测试产物；**删掉即净**，工程源码一个字节没动 |
| `<工程>/run/saves/mctestagent_*` | 测试世界 | `run --world-mode create` 时默认**先清掉上一轮的**（只删 `mctestagent` 开头的） |
| `<工程>/run/options.txt` | 代理会写 `pauseOnLostFocus:false` | **这是自动化能跑的前提**（§5.3），不是副作用；`guiScale`/`renderDistance` 默认**不动**（要改用 `--gui-scale/--render-distance`） |

`git status` 里只会看到 `run/` 下的东西（正常工程都不提交 run 目录）。

### 4.3 代理支持的动作（inbox 里一行一条 JSON）

分两层。**①是"上帝模式"（发命令、看数据），②是"真的把手指按下去"** —— 两者都要，
因为 `/setblock` 放出来的方块**不会**触发 mod 的 `useItemOn`。

**① 引擎 / 观察层**

| op | 参数 | 说明 |
|---|---|---|
| `cmd` | `command` | 以玩家身份执行命令（自动去 `/`） |
| `wait` | `ticks` | 等 N tick |
| `wait_for` | `what`=`world`/`no_screen`/`screen`/`chat`/`block`/`tick`、`value`、`timeout` | 等条件成立 |
| `shot` | `name`、`downscale` | 截图（framebuffer，含 HUD/界面） |
| `key` | `mapping`（翻译键，如 `key.jump`）、`state`=`tap`/`down`/`up` | 按一下/按住某个**按键映射** |
| `screen` | `action`=`open`/`close`/`dump`/`click`/`click_at`/`type`、`value` | 界面操作；`click` 按**翻译键**找控件 |
| `state` | `radius`、`withBlocks` | 导出完整状态（见 §4.4） |
| `block` | `pos`=`"x,y,z"` | 读单方块 |
| `entities` | `radius` | 附近实体 |
| `chat` | `pattern`、`all` | 命令回显/聊天缓冲 |
| `log` | `lines`、`pattern`、`fromLine` | 读 `logs/latest.log` 尾部 |
| `quit` | `code`、`reason` | 退出（走 `Minecraft.stop()`，和点窗口 X 同一条路） |

**② 玩家输入层（真的按下去）**

| op | 参数 | 说明 |
|---|---|---|
| `move` | `direction`=`forward`/`back`/`left`/`right`、`ticks`、`sprint`、`sneak` | **走路**：按住方向键 N tick（可叠疾跑/潜行）。返回 `{keys, from, to, ticks}` —— 起终点坐标就是"真走了"的证据 |
| `jump` | `ticks` | 按跳跃键 |
| `look` | `yaw` / `pitch` / `target`（世界点 `"x,y,z"`） | **转向**；返回 `crosshair`（准星实际命中哪个方块/哪一面。做 `place`/`mine` 前先看它，比猜快得多） |
| `use` | `ticks` | **右键**：用物品 / 放置 / 交互实体。`ticks>1` 按住（测吃东西、拉弓） |
| `mine` | `pos`、`ticks` | **左键**：挖方块（给 `pos` 会先自动瞄准）/ 打实体。返回 `{block,pos,broken}` |
| `place` | `pos`=`"x,y,z"` | **在目标位置放一块**：自动找贴靠块 → 瞄准该面中心 → 校验准星真的落在上面 → 右键。⚠️ 走的是**玩家右键那条路，mod 的 `useItemOn` 会被触发** |
| `hotbar` | `slot`=1~9 | 切快捷栏 |
| `drop` | — | 丢出（Q） |
| `open_inventory` | — | **真按 E 开背包**。返回 `screen` + `container`（每个槽位的**屏幕坐标** `x/y` 与物品） |
| `swap_hands` | — | 主副手交换（F） |
| `container` | `action`=`dump`/`click`/`close`、`slot`、`button`、`shift` | 容器界面：列槽位 / 点槽位（`shift=true` 是 Shift 快速移动）/ 关掉。点槽位走的是**真实点击那条路**（屏幕 `slotClicked` 内部也是调它） |
| `say` | `text` | 发一条聊天消息（测聊天类功能） |

**这三层的实现要点**（写在 `templates/测试代理-26.1/…/Input.java` 的类注释里）：

| 动作 | 怎么实现的 | 为什么不能更省事 |
|---|---|---|
| 移动 / 跳 / 潜行 / 疾跑 / 快捷栏 / 开背包 | 直接改 `KeyMapping` 的按下状态 —— 原版每 tick 自己读 `isDown()` | 这就是"真按键"，不是作弊式位移；按键改造类 mod 才会被真的触发 |
| 右键 / 左键单击 | 复刻 `Minecraft.startUseItem()` / `startAttack()` 的公开 API 调用链 | 那两个方法本身**是包私有的**，跨包调不到 |
| 持续挖掘 | 直接调 `MultiPlayerGameMode.continueDestroyBlock()` | 原版 `continueAttack` 要求 `mouseHandler.isMouseGrabbed()` —— **窗口一失焦就是 false**，「按住左键挖」在无人值守时根本不跑 |

⚠️ **有界面打开时，玩家输入层会直接被拒**（`move`/`use`/`mine`/`place` 都会查 `mc.screen`）——
因为按键/右键会被界面吃掉。先 `screen close` 或 `container close`。

### 4.4 `state` 导出什么

`client`（界面类名/窗口尺寸/帧率/`pauseOnLostFocus`）、`player`（坐标/朝向/血量/饥饿/等级/游戏模式/
潜行/疾跑/飞行/维度/状态效果原文，+ `crosshair` 准星命中）、`world`（gameTime/时辰近似/天气/难度）、
`inventory`（36 格非空槽 + 选中槽 + 副手 + 四件护甲）、`entities`、`blocks`（可选）。
**断言全部在外部（Python）做** —— 这样加一条新判据不用重编 Java。

### 4.5 Python 侧方法（中文名，和上面第二张表一一对应）

| Python | 对应 op | 备注 |
|---|---|---|
| `agent.移动(direction="forward", ticks=20, sprint=False, sneak=False)` | `move` | 返回 `{from,to}`；断言写"起终点不同"比写死位移量稳（会被地形挡） |
| `agent.跳(ticks=1)` | `jump` | |
| `agent.看向(yaw=,pitch=,target=)` / `agent.看向方块("5,64,5")` | `look` | `看向方块` 自动 +0.5 瞄准**方块中心** |
| `agent.右键(ticks=1)` | `use` | |
| `agent.挖(pos=None, ticks=200)` | `mine` | 返回 `{block,pos,broken}` |
| `agent.放置("5,64,5")` | `place` | 返回 `{target,against,face,distance,result}` |
| `agent.快捷栏(3)` / `agent.丢出()` | `hotbar` / `drop` | |
| `agent.开背包()` | `open_inventory` | |
| `agent.容器("dump")` / `agent.点格子(36, shift=True)` / `agent.关容器()` | `container` | 点格子前先 `dump` 拿槽位序号 |
| `agent.说话("hi")` | `say` | |

⭐ **"验我做的方块，能不能被玩家真的放下来 + 右键有没有反应"** 的完整套路：

```python
agent.进世界()
agent.命令("give @s minecraft:stone 64")   # 手里得有方块，否则 place 直接失败
agent.命令("tp 0 100 0")                    # 先站到一块平地上再走，别让地形挡
agent.等(10)
agent.快捷栏(1)

r = agent.移动("forward", ticks=20)         # 真按住 W 走两步
assert r["from"] != r["to"], r

st = agent.状态()
x, y, z = [float(v) for v in st["player"]["pos"].split(",")]
目标 = f"{int(x)+2},{int(y)-1},{int(z)}"     # 脚下前方那块（按你的场景算）
res = agent.放置(目标)                      # 走玩家右键路径 → mod 的 useItemOn
assert agent.方块(目标) == "你的mod:方块id", res
assert agent.方块(f"{int(x)+2},{int(y)},{int(z)}") == "minecraft:air"   # 负样本：判据不能恒真

agent.开背包()                              # 真按 E
inv = agent.容器("dump")
assert inv["open"] is True and len(inv["slots"]) > 0, inv
agent.截图("走位+放置+背包")
```

要点：`place` 的返回里有 `against`（贴靠哪块）/ `face`（哪一面）/ `distance` —— **失败时先看这三个**，
比"方块没出现"好定位得多（悬空放不了、超 4.5 格、视线被挡，都会在这里体现）。

## 5. 实测出来的坑（都是这次真踩的）

### 5.1 ⭐ 本机 `runClient` **本来就能到主菜单** —— 旧结论是误判，已更正

本 skill 早前的 §7⑥ 写着"本机 `runClient` 只能跑到资源重载阶段（`Loaded 0 entity animations`
之后无输出），起不到游戏里"。**这是把"看不到"当成了"起不来"。**

实测证据（2026-10-08）：

```
窗口列表：'Minecraft NeoForge* 26.1'  class=GLFW30  size=584x357
PrintWindow 抓图 → 标题界面：欢迎界面 + Minecraft Java Edition LOGO
```

客户端日志停在 `Loaded 0 entity animations` 之后就**不再打日志是正常的**（主菜单不上报），
进程也不是"空转"—— 它就是在标题界面等你操作。
**教训：日志停住 ≠ 卡住。要么看窗口，要么看进程在不在。**

### 5.2 无障碍引导界面会挡在标题界面前面

首次运行客户端会出现 `AccessibilityOnboardingScreen`（"Welcome to Minecraft!"）。
代理的启动流程里专门有一拍处理它：只认 `gui.continue` / `gui.ok` / `gui.acknowledge`，
点不到就把控件清单打出来 —— **绝不乱点**（乱点可能点进"辅助功能设置"里出不来）。

⚠️ 点击要**带冷却**（40 tick）。点完的下一 tick 界面还没切走，无脑重试会在日志里刷一串
"点掉引导界面按钮"（实测连点 4 次）。

### 5.3 🔴 `pauseOnLostFocus` 必须关 —— 否则世界会静止

`Options.pauseOnLostFocus` 默认 `true`。**窗口一失去焦点，单人世界自动暂停**，
整个世界 tick 全停：实体不动、时间不走、`/setblock` 之后的状态读起来像"没生效"。
而这一切**日志里一声不响**。

代理在启动阶段会把它置 `false` 并 `options.save()`（写进 `options.txt`），
`state.client.pauseOnLostFocus` 可以直接断言。

> **推广**：任何"无人值守跑客户端"的方案，第一条就要关这个。

### 5.4 建世界：不要手搓 `LevelSettings/WorldOptions`

手搓要凑齐 `LevelSettings(levelName, GameType, DifficultySettings, allowCommands, WorldDataConfiguration)`
+ `WorldOptions` + `Function<RegistryAccess, WorldDimensions>` 三件套，还容易漏掉数据包/注册表接线。
**照 Fabric 的做法走界面**：

```java
CreateWorldScreen.openFresh(mc, () -> mc.setScreen(old));   // 先开界面
// 等 mc.screen instanceof CreateWorldScreen（它是异步出现的！）
WorldCreationUiState ui = cws.getUiState();
ui.setName(...); ui.setSeed(...); ui.setGenerateStructures(...);
ui.setWorldType(new WorldCreationUiState.WorldTypeEntry(预设Holder));
ui.setGameMode(WorldCreationUiState.SelectedGameMode.CREATIVE);   // ⚠️ 常量在嵌套类上
ui.setAllowCommands(true);                                        // = 开作弊，玩家自动 OP
Ui.find(screen, "selectWorld.create") → 点它
```

`allowCommands=true` 是关键：单机世界里开了作弊，玩家就是 OP，`/give` `/setblock` `/time` 全部可用。

### 5.5 26.1 的 API 重命名（写代码前先看这张表，省一轮编译）

| 你以为是 | 26.1 实际是 |
|---|---|
| `ResourceLocation` / `ResourceKey.location()` | `Identifier` / `ResourceKey.identifier()` |
| `GuiGraphics` | `GuiGraphicsExtractor`（`AbstractWidget.extractWidgetRenderState(...)`） |
| `AbstractWidget.mouseClicked(double,double,int)` | `onClick(MouseButtonEvent, boolean)` / `onRelease(MouseButtonEvent)` |
| `Screen.keyPressed(int,int,int)` | `keyPressed(KeyEvent)` |
| `WorldCreationUiState.CREATIVE` | `WorldCreationUiState.SelectedGameMode.CREATIVE`（在**嵌套类**上） |
| `level.getDayTime()` | **不存在**（`LevelData` 里也没有 dayTime）→ 用 `gameTime % 24000` 近似，或跑 `/time query daytime` 读回显 |
| `Screenshot.grab(File, Window, Consumer)` | `Screenshot.grab(File, RenderTarget, Consumer)` / `takeScreenshot(RenderTarget, downscale, Consumer)` |
| `KeyMapping.getKey()` | 公开 API 里没有（只有 `getDefaultKey()`）→ 反射取，取不到退回默认键 |

> 自查这些签名用 `python scripts/JarSig.py <jar> <类名>`；
> **本机还有反编译源码**可用（比 javap 友好得多）：
> `<工程>/build/moddev/artifacts/minecraft-patched-<版本>-sources.jar`。

代理 `System.out.println` 的中文在 Gradle 日志里是乱码（子进程默认编码 GBK × 日志按 UTF-8 读）：

```
[mctestagent] ���Դ����Ѽ��أ�����Ŀ¼ D:\…\run\���Դ���
```

**产物不受影响**（JSONL 是显式 UTF-8 写的），但人读的诊断就瞎了。
所以 `Io.warn()` 同时追加写 `测试代理/代理.log`。**排查问题先看这个文件。**

### 5.7 截图抓的是 framebuffer 的内容 → 改完状态要等

`Screenshot.takeScreenshot(RenderTarget, …)` 读的是主渲染目标（上一帧画完的东西）。
改完界面/放完方块**下一 tick 就截图**，很可能截到旧画面。
**规矩：`shot` 前面留 ≥2 tick**（`{"op":"wait","ticks":3}`）。

截图尺寸 = 窗口 framebuffer（实测 854×480，与 `guiScale` 无关）；够 AI 看清 HUD/界面，也够人看。

### 5.8 命令是**异步**的：发完立刻读状态会读到旧值

`/setblock` 走 客户端 → 集成服务端 → 回包 的往返，主线程上返回时世界还没变。
实测：`{"op":"cmd"}` 在 `elapsed=1` tick 就返回了结果，但方块要到之后才变。

**规矩：`cmd` 后面接 `wait`（5~10 tick）再读。** 已经见过"明明破坏了却查到还在"
这类假结论（服务端 RCON 那边也是同一个坑，见 `专用服务端自动化验证.md` §8.3）。

### 5.9 代理的动作必须**串行**

一次只跑一个动作，前一个出结果才发下一个。
并发发命令会让"因果"没法归因，断言就全是猜的。
`状态.json` 里的 `current` / `pending` 能看出队列有没有堵。

### 5.9b 玩家输入层的四个"一次就中招"

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `move` / `use` / `mine` / `place` 直接返回失败，提示"有界面打开着" | 这些动作都查 `mc.screen` —— 界面开着时按键/右键会被界面吃掉 | 先 `screen close` 或 `container close` |
| `place` 失败："手上没拿东西" | 放置走的是"右手真的拿着一块"这条路 | `cmd give` / `hotbar` 切到有方块的格子 |
| `place` 失败："四周没有可贴靠的方块（悬空放不了）" / "距离超过 4.5" | 原版放置本来就要贴靠面 + 距离上限，这是**玩家真的会遇到的限制**，不是 bug | 先 `/tp` 到目标旁边；或拿它当"放置合法性"的正面证据 |
| 走了但坐标几乎没动 | 前面有墙/水/悬崖，或者**世界没开 cheat 时 `tp` 也没生效**导致站位不对 | 先 `cmd tp` 到平地，再 `move`；断言写"起终点不同"而不是写死格数 |

### 5.9c 转向是"瞬间设置"，而且服务端要等一 tick

`look` 里是 `player.setYRot/setXRot` —— **不是**鼠标划过去，没有插值/平滑。
而且 `useItemOn` 在服务端会**校验视线**，客户端自己重算 `hitResult` 也要一 tick，
所以代理内部固定等 3 tick 才返回（返回里的 `crosshair` 就是等完之后的真实命中）。
要测"鼠标灵敏度/平滑/输入延迟"这类，本工具不覆盖，交给人。

### 5.10 退出：`Minecraft.stop()` 就是正解

```java
public void stop() {
    if (this.isRunning()) NeoForge.EVENT_BUS.post(new GameShuttingDownEvent());
    this.running = false;              // ← 只是翻个标志，主循环下一轮自己走正常关闭
}
```

所以在 tick 里直接调是安全的（和点窗口 X 同一条路，会正常存档、写日志、`Stopping!`）。
外部兜底用 `WM_CLOSE`（`PostMessage(hwnd, 0x0010, 0, 0)`）—— 同样优雅，实测 gradle 以 `BUILD SUCCESSFUL` 收尾。

| HUD/界面 | `screen open <类名>` 或 `key <翻译键>` → `wait` → `shot`；`screen dump` 列控件 |
| 按钮副作用 | `screen click <翻译键>` → `wait` → `state`/`block` 验证 |
| 按键绑定 | `key key.xxx tap` → 看 mod 的效果（聊天/状态/界面） |
| 我的方块能不能被放下来 + 右键有没有反应 | `hotbar` 切到手里有方块 → `place x,y,z` → `block` 验方块 + `state`/`chat` 验右键副作用 |

| 打开背包 / 动槽位 | `open_inventory` → `container dump` → `container click slot=36 shift=true` → 再 `dump` 对比 |
| 有没有异常 | 报告里的 `客户端异常`；或 `log pattern=ERROR\|Exception` |

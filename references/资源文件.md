# 资源与数据文件写法

mod 的「看不见的部分」——模型、材质、语言、配方、战利品表、标签。**资源路径与注册 id 不一致是新手最常犯的错**（游戏内表现为紫黑方块/缺失材质）。

> 本文件所有 JSON 均为**严格 JSON**：不能有注释、不能有尾逗号。1.21.6 起游戏对所有 JSON 启用严格解析，容错为零。

---

## 1. 目录结构总览

```
src/main/resources/
├── pack.mcmeta                          # 可选，声明 pack 格式
├── assets/<modid>/                      # 客户端资源
│   ├── blockstates/<方块id>.json         # 方块状态→模型映射
│   ├── models/
│   │   ├── block/<方块id>.json           # 方块模型
│   │   └── item/<物品id>.json            # 物品模型（1.21.3 及以前的主写法）
│   ├── items/<物品id>.json               # ★ 物品模型定义（1.21.4+ 新增）
│   ├── textures/
│   │   ├── block/<方块id>.png
│   │   └── item/<物品id>.png
│   ├── lang/
│   │   ├── en_us.json
│   │   └── zh_cn.json
│   └── particles/ 、sounds/ 、font/ ...
└── data/<modid>/                        # 服务端数据
    ├── recipe/<配方id>.json              # ★ 1.21 起单数
    ├── loot_table/blocks/<方块id>.json    # ★ 原 loot_tables
    ├── tags/
    │   ├── block/<标签名>.json            # ★ 原 tags/blocks
    │   └── item/<标签名>.json
    ├── advancement/<id>.json
    └── ...
```

### ⚠️ 目录名去复数（1.21 起）

| 旧（≤1.20.6） | 新（1.21+） |
|---|---|
| `recipes/` | `recipe/` |
| `loot_tables/` | `loot_table/` |
| `advancements/` | `advancement/` |
| `structures/` | `structure/` |
| `tags/blocks/` | `tags/block/` |
| `tags/items/` | `tags/item/` |
| `tags/entity_types/` | `tags/entity_type/` |
| `tags/fluids/` | `tags/fluid/` |
| `tags/game_events/` | `tags/game_event/` |
| `predicates/` | `predicate/` |
| `item_modifiers/` | `item_modifier/` |
| `functions/` | `function/` |

> 1.20.1 工程用左侧旧名，1.21+ 用右侧新名。写错则资源不生效且**不报错**，极难排查。

## 2. pack.mcmeta

```json
{
  "pack": {
    "pack_format": 88,
    "description": "My Mod resources"
  }
}
```

1.21.9 起 pack_format 变为**小数**，并要求同时写 `min_format` / `max_format`：

```json
{
  "pack": {
    "pack_format": 88.0,
    "min_format": 88.0,
    "max_format": 88.0,
    "description": "My Mod resources"
  }
}
```

各版本取值见 `版本差异矩阵.md` 第 1 节。（26.1：data 101.1 / res 84.0；26.2：data 107.1 / res 88.0）

> 多数 mod 不需要 pack.mcmeta——官方 26.x 模板里就没有，资源会合并进 "Mod Resources" 内置包。需要独立资源包时才加。

## 3. 方块状态 blockstates

**所有方块状态**写在一个文件里：

```json
{
  "variants": {
    "": { "model": "mymod:block/my_block" }
  }
}
```

带属性的（如朝向）：
```json
{
  "variants": {
    "facing=north": { "model": "mymod:block/my_block" },
    "facing=east":  { "model": "mymod:block/my_block", "y": 90 },
    "facing=south": { "model": "mymod:block/my_block", "y": 180 },
    "facing=west":  { "model": "mymod:block/my_block", "y": 270 }
  }
}
```

多条件用 `multipart`：
```json
{
  "multipart": [
    { "when": { "north": "true" }, "apply": { "model": "mymod:block/pipe_side" } },
    { "apply": { "model": "mymod:block/pipe_core" } }
  ]
}
```

## 4. 方块模型

**cube（六面同材质）**：
```json
{
  "parent": "minecraft:block/cube_all",
  "textures": { "all": "mymod:block/my_block" }
}
```

**cube_all 的替代父模型**（常用，省事）：
- `minecraft:block/cube_all` — 六面同一张
- `minecraft:block/cube_bottom_top` — 顶/底/侧不同（如草方块）
- `minecraft:block/cube_column` — 竖柱（原木）
- `minecraft:block/cube` — 自定义每面
- `minecraft:block/cross` — 十字（花草）
- `minecraft:block/slab` / `stairs` / `fence` / `wall` 等

**自定义每面**：
```json
{
  "parent": "minecraft:block/cube",
  "textures": {
    "particle": "mymod:block/front",
    "down":  "mymod:block/bottom",
    "up":    "mymod:block/top",
    "north": "mymod:block/front",
    "south": "mymod:block/side",
    "west":  "mymod:block/side",
    "east":  "mymod:block/side"
  }
}
```

纹理引用规则：`mymod:block/my_block` → `assets/mymod/textures/block/my_block.png`

## 5. 物品模型

### 5.1 普通物品（通用写法，全版本可用）

`assets/<modid>/models/item/<物品id>.json`：
```json
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "mymod:item/my_item"
  }
}
```
→ 对应 `assets/mymod/textures/item/my_item.png`

**手持工具/武器**用 `minecraft:item/handheld`。

### 5.2 方块物品（让物品显示成方块的样子）

```json
{
  "parent": "mymod:block/my_block"
}
```

### 5.3 ★ 物品模型定义（1.21.4+）

1.21.4 起，物品模型**定义**与**模型**分离：物品先找 `assets/<modid>/items/<物品id>.json`，再由它指向 `models/item/` 下的模型。

`assets/<modid>/items/my_item.json`：
```json
{
  "model": {
    "type": "minecraft:model",
    "model": "mymod:item/my_item"
  }
}
```

可用的 `type`（1.21.4+）：

| type | 作用 |
|---|---|
| `minecraft:model` | 直接指向一个模型 |
| `minecraft:composite` | 叠加多个模型（如盔甲分层） |
| `minecraft:condition` | 按布尔属性二选一 |
| `minecraft:select` | 按枚举属性选择 |
| `minecraft:range_dispatch` | 按数值属性区间选择（**取代旧的 custom_model_data overrides**） |
| `minecraft:special` | 特殊内置模型（盾牌、头颅、钟等） |
| `minecraft:empty` | 空模型 |
| `bundle/selected_item` | 收纳袋选中物品 |

**取代 custom_model_data 的写法**（重要）：
```json
{
  "model": {
    "type": "minecraft:range_dispatch",
    "property": "minecraft:custom_model_data",
    "entries": [
      { "threshold": 1.0, "model": { "type": "minecraft:model", "model": "mymod:item/variant_a" } },
      { "threshold": 2.0, "model": { "type": "minecraft:model", "model": "mymod:item/variant_b" } }
    ],
    "fallback": { "type": "minecraft:model", "model": "mymod:item/my_item" }
  }
}
```

**按组件条件**（如鞘翅损坏）：
```json
{
  "model": {
    "type": "minecraft:condition",
    "property": "minecraft:broken",
    "on_false": { "type": "minecraft:model", "model": "minecraft:item/elytra" },
    "on_true":  { "type": "minecraft:model", "model": "minecraft:item/elytra_broken" }
  }
}
```

**按是否潜行显示不同模型**（按键绑定）：
```json
{
  "model": {
    "type": "minecraft:condition",
    "property": "minecraft:keybind_down",
    "keybind": "key.sneak",
    "on_true":  { "type": "minecraft:model", "model": "mymod:item/my_item_alt" },
    "on_false": { "type": "minecraft:model", "model": "mymod:item/my_item" }
  }
}
```

> **1.20.1 / 1.21.3 及以前**：不要写 `items/` 目录，直接在 `models/item/` 里用 `"overrides": [{ "predicate": {"custom_model_data": 1}, "model": "..." }]`。

## 6. 语言文件

`assets/<modid>/lang/zh_cn.json`：
```json
{
  "item.mymod.my_item": "我的物品",
  "block.mymod.my_block": "我的方块",
  "itemGroup.mymod": "我的模组",
  "container.mymod.my_container": "我的容器",
  "death.attack.mymod.my_damage": "%s 被 %s 干掉了",
  "commands.mymod.hello": "你好，%s"
}
```

**lang key 命名规则**：
| 类型 | 格式 | 示例 |
|---|---|---|
| 物品 | `item.<modid>.<id>` | `item.mymod.my_item` |
| 方块 | `block.<modid>.<id>` | `block.mymod.my_block` |
| 创造栏 | `itemGroup.<modid>` | `itemGroup.mymod` |
| 实体 | `entity.<modid>.<id>` | `entity.mymod.my_mob` |
| 附魔 | `enchantment.<modid>.<id>` | |
| 药水效果 | `effect.<modid>.<id>` | |
| 容器标题 | `container.<modid>.<id>` | |
| 提示/信息 | 自定义，建议以 modid 开头 | `mymod.message.foo` |

文件必须是 **UTF-8 无 BOM**。Gradle 里已配 `options.encoding = 'UTF-8'`。

死亡信息等带参数的用 `%s`（按顺序）或 `%1$s`（按索引）。

## 7. 配方

### 有序合成 `data/<modid>/recipe/<id>.json`
```json
{
  "type": "minecraft:crafting_shaped",
  "pattern": [
    "XXX",
    " # ",
    " # "
  ],
  "key": {
    "X": { "item": "mymod:my_ingot" },
    "#": { "tag": "minecraft:sticks" }
  },
  "result": { "id": "mymod:my_pickaxe" }
}
```
> 1.21 起 `result` 推荐用 `{"id": "..."}` 并可加 `"count"`；旧写法 `{"item": "...", "count": 1}` 在 1.21.2+ 仍兼容但已不推荐。1.20.1 用 `{"item": "...", "count": 1}`。

### 无序合成
```json
{
  "type": "minecraft:crafting_shapeless",
  "ingredients": [
    { "item": "mymod:my_dust" },
    { "item": "minecraft:water_bucket" }
  ],
  "result": { "id": "mymod:my_paste", "count": 2 }
}
```

### 熔炼 / 高炉 / 烟熏 / 营火
```json
{
  "type": "minecraft:smelting",
  "ingredient": { "item": "mymod:my_ore" },
  "result": { "id": "mymod:my_ingot" },
  "experience": 0.7,
  "cookingtime": 200
}
```
`cookingtime`：熔炉 200，高炉 100，烟熏 100，营火 600。

### 切石机
```json
{
  "type": "minecraft:stonecutting",
  "ingredient": { "item": "mymod:my_stone" },
  "result": { "id": "mymod:my_stone_slab", "count": 2 }
}
```

### 锻造台（升级装备）
```json
{
  "type": "minecraft:smithing_transform",
  "template": { "item": "minecraft:netherite_upgrade_smithing_template" },
  "base": { "item": "mymod:my_sword" },
  "addition": { "item": "mymod:my_upgrade" },
  "result": { "id": "mymod:my_sword_upgraded" }
}
```

### 酿造台
```json
{
  "type": "minecraft:brewing",
  "ingredient": { "item": "mymod:my_herb" },
  "input": { "item": "minecraft:awkward_potion" },
  "result": { "id": "minecraft:potion", "components": { "minecraft:potion_contents": { "potion": "mymod:my_effect" } } }
}
```
> 1.20.5+ 药水/食物等用 **components** 而非 NBT。1.20.4 及以前用 `"result": {"item": "...", "nbt": {...}}`。

## 8. 战利品表

### 方块掉落 `data/<modid>/loot_table/blocks/<方块id>.json`
```json
{
  "type": "minecraft:block",
  "pools": [
    {
      "rolls": 1,
      "bonus_rolls": 0,
      "entries": [
        {
          "type": "minecraft:item",
          "name": "mymod:my_block"
        }
      ],
      "conditions": [
        {
          "condition": "minecraft:survives_explosion"
        }
      ]
    }
  ]
}
```

**带精准采集**：
```json
{
  "type": "minecraft:block",
  "pools": [
    {
      "rolls": 1,
      "entries": [{ "type": "minecraft:item", "name": "mymod:my_ore" }],
      "conditions": [
        { "condition": "minecraft:match_tool", "predicate": { "predicates": { "minecraft:enchantments": [{ "enchantment": "minecraft:silk_touch", "levels": { "min": 1 } }] } } }
      ]
    },
    {
      "rolls": 1,
      "entries": [{ "type": "minecraft:item", "name": "mymod:raw_ore" }],
      "conditions": [{ "condition": "minecraft:survives_explosion" }]
    }
  ],
  "functions": [
    { "function": "minecraft:apply_bonus", "enchantment": "minecraft:fortune", "formula": "minecraft:ore_drops" },
    { "function": "minecraft:explosion_decay" }
  ]
}
```

> ⚠️ **忘了写 loot_table = 方块掉落空气**。这是最常见的"我明明加了方块但不掉东西"。

### 实体掉落 `data/<modid>/loot_table/entities/<实体id>.json`
```json
{
  "type": "minecraft:entity",
  "pools": [
    {
      "rolls": 1,
      "entries": [{ "type": "minecraft:item", "name": "mymod:my_drop" }],

```

### 宝箱 `data/<modid>/loot_table/chests/<id>.json`
```json
{
  "type": "minecraft:chest",
  "pools": [
    {
      "rolls": { "min": 2, "max": 4 },

        { "type": "minecraft:item", "name": "mymod:my_item", "weight": 10 },
```

## 9. 标签 Tags

### 物品标签 `data/<modid>/tags/item/<名字>.json`
```json
{
  "values": [
    "mymod:my_ingot",
    "mymod:my_nugget"
  ]
}
```

### 引用原版或别家标签
```json
{
  "values": [
    "#minecraft:planks",
    "#c:ingots"
  ]
}
```
`#` 前缀表示引用另一个标签。

### 方块标签 `data/<modid>/tags/block/<名字>.json`
```json
{
  "values": [
    "mymod:my_ore",
    "#minecraft:overworld_carvable"
  ]
}
```

**常用原版标签**：
| 用途 | 标签 |
|---|---|
| 可被镐挖 | `minecraft:mineable/pickaxe` |
| 需要石镐以上 | `minecraft:needs_stone_tool` |
| 需要铁镐以上 | `minecraft:needs_iron_tool` |
| 需要钻石镐以上 | `minecraft:needs_diamond_tool` |
| 主世界可生成矿石 | `minecraft:overworld_carvable`（1.21+） |

**挖矿工具与等级**（1.20.5+ 用标签，旧版写在方块属性里）：
```json
{
  "values": ["mymod:my_ore"]
}
```
放到 `data/minecraft/tags/block/mineable/pickaxe.json` 表示**覆盖/追加**原版标签（需加 `"replace": false`，默认即为追加）：
```json
{
  "replace": false,
  "values": ["mymod:my_ore"]
}
```

## 10. 进度 Advancements

`data/<modid>/advancement/<id>.json`：
```json
{
  "parent": "minecraft:story/root",
  "criteria": {
    "got_item": {
      "trigger": "minecraft:inventory_changed",
      "conditions": { "items": [{ "items": ["mymod:my_item"] }] }
    }
  },
  "requirements": [["got_item"]],
  "rewards": { "experience": 100 },
  "display": {
    "icon": { "id": "mymod:my_item" },
    "title": { "translate": "advancement.mymod.my_advancement.title" },
    "description": { "translate": "advancement.mymod.my_advancement.description" },
    "frame": "task",
    "show_toast": true,
    "announce_to_chat": true,
    "hidden": false
  }
}
```

> 1.21 起 `conditions.items[].items` 支持直接写物品 id 数组；1.20.x 用 `"items": [{"item": "mymod:my_item"}]`。
> 1.20.5+ 的 `icon` 用 `{"id": "..."}`（可加 components），旧版用 `{"item": "..."}`。

## 12. 常见翻车点清单

| 症状 | 原因 |
|---|---|
| 物品/方块显示紫黑（棋盘格） | ①模型 JSON 路径与注册 id 不一致；②纹理路径写错（**含贴图文件根本不存在**，见 §13）；③模型 JSON 语法错误 |
| 方块不掉落 | 没写 `loot_table/blocks/<id>.json` |
| 配方不生效 | ①目录名写成 `recipes/`（1.21+ 应为 `recipe/`）；②JSON 里有注释 |
| 中文变乱码 | 文件不是 UTF-8 无 BOM |
| 创造栏里找不到物品 | 没在 `displayItems` 或 `BuildCreativeModeTabContentsEvent` 里 `accept` |
| 方块挖不动 | 没加 `mineable/pickaxe` 标签 + 硬度设置 |
| 模型更新了但游戏里没变 | 需要重新加载资源（F3+T），或 datagen 输出被缓存 |
| 1.21.6+ 报 JSON 解析错 | 写了注释或尾逗号，严格模式下不合法 |

## 13. 引用完整性：跑一把静态检查（2026-10-14 新增）

**真实案例**：位面模组的 `models/block/plane_core.json` 一直引用
`planes:block/plane_core`，但 `textures/block/plane_core.png` **从来没生成过**；
另外 4 个盔甲 item 贴图同样缺失。结果：游戏里那个方块/物品是**紫黑棋盘格**，
而 **`gradlew build`、静态门禁、服务端 selftest 全都不报** ——
客户端只在日志里留一行 `Missing textures in model planes:plane_core#:`。

### 用 `scripts/资源引用校验.py`

```bash
python scripts/资源引用校验.py <mod工程目录>
python scripts/资源引用校验.py <工程> --modid 自定义id    # 推断不出来时指定
```

它扫 `assets/<ns>/**/*.json` 的全部四类引用：

| 来源 | 检查 |
|---|---|
| `models/**` 的 `textures` 段值 | `<ns>:block/x` → `textures/block/x.png`；`item` / `models/armor` 同理 |
| `models/**` 的 `parent` | `<ns>:block/x` → `models/block/x.json` |
| `blockstates/**` 的 `variants`/`multipart` 里的 `model` | 同上 |
| 任何 JSON 解析失败 | 直接报错（严格模式下会**静默丢弃**整个模型） |

modid 推断顺序：`--modid` → `gradle.properties` 的 `mod_id` → `assets/` 下唯一的非 `minecraft` 目录。

**验证方法（做反证，别只信绿）**：临时把任意一张被引用的贴图挪走，脚本必须报出那一条。
反证过才算「这道检查真的在工作」。

### 排查紫黑方块的三步

1. **看客户端日志**：`Missing textures in model <ns>:<name>#:` —— 名字直接告诉你缺哪个
2. **跑本脚本**：一次性列出全部悬空引用（含 parent 链）
3. **看 jar 内容**：`unzip -l build/libs/*.jar | grep textures` ——
   确认文件真的被打进包（有时是 `processResources` 漏了、或文件在错误的 source set 里）

## 14. element 的 `rotation`：斜插卡片 / 斜切板（2026-10-24 实测）

MC 的 element 支持绕一根轴旋转，这是**唯一**能用方块模型表达"斜着插的一片"的办法
（斜屋顶、斜撑、植物的叶片卡片）。三个硬限制 + 一个符号坑：

| 项 | 规则 |
|---|---|
| 字段 | `"rotation": {"origin": [x,y,z], "axis": "x\|y\|z", "angle": deg, "rescale": bool}` |
| `angle` | **只能是 22.5 的整数倍，且限制在 ±45** —— 这是 MC 侧的校验，写 30 整块模型加载失败 |
| `rescale` | `true` 会把元素按旋转后的包围盒拉伸（栅栏那种"接缝填满"用），卡片必须写 `false` |
| `origin` | 旋转的支点（0..16 单位空间）。**放在卡片中心**才不会被甩到别处 |

### 🔴 旋转方向：别凭印象，实测一次

MC 走的是 `CuboidRotation$SingleAxisRotation.transformation()` →
`new Matrix4f().rotation(angle * π/180, axis.getPositive())`，**没有取负**。
JOML 1.10.8 实测（`--axis=+Y`、+45°）：

```
R·X = (cos, 0, -sin)      R·Z = (sin, 0, cos)
```

符号写反的后果很阴：卡片会落在**镜像的那条对角线**上 —— 牌还在、角度也合法、
肉眼几乎看不出，只有拿坐标硬对才现形。判据：把卡片四角按上式转回去，
和源几何的顶点逐个比距离（≤0.5 单位合格），实测可做到 **0.00**。

### 任意朝向怎么凑（两个基准面）

只用一个基准面时，`angle ∈ [-45,45]` 只能表达 ±45 范围内的法线朝向。
把"基准面"选成 X 面（法线 +X）或 Z 面（法线 +Z），两套合起来才覆盖 360°：

```
基准 X 面转 θ  → 法线落在 θ 上
基准 Z 面转 θ  → 法线落在 θ-90 上
```

量化到最近一档 22.5° 后，误差 >12° 的**直接放弃**（宁可少一片，不能歪成别的平面）。

### 🔴 两个配套坑：零厚度板 + 双面片

从外部模型（obj/glb）转 element 时这条链最容易翻车：

1. 每张板只出一个面 → MC 剔除背面 → 从背后看是空的。
   必须**同一平面写 face + 它的对面**两条（uv 不镜像）。
2. 源模型里"正面片 + 反面片"常是两条独立四边形，转完是**两个完全相同的 element**
   （各自都已带正反两面）。此时任何"同平面 + 同矩形 + 朝向相反就删"的去重逻辑
   会把它们**两两互删** —— 表现是"模型还在、主体没了"（实测 6 盆室内植物只剩花盆，
   高度只有源模型的 8%~26%）。正确做法是**同位置只留一块**，不是两块都删。

> 判据不能只查"模型文件合法"（贴图/引用/尺寸全绿也照样丢主体）。
> 要查**主体还在不在**：高宽比守恒（尺度无关）+ 卡片四角逐角复原。
> 实战记录：`僵尸计划` 的 `tools/check_cards.py`（schema / 高宽比 / 至少一张牌 / 逐角复原 / 双向自检）。

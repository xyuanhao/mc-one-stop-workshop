# 验证判据设计 —— 生成类内容的验收

> **什么时候看这份**：做**生成类**内容（地形、结构、方块摆放、含水洞穴、植被分布）时——
> 也就是"生成**不报错**，但结果是**错**的"那一类。
>
> 这份文档的来源是一次真实的十五轮迭代：一个自定义维度地形生成器，
> 其中**判据自己出错 5 次**，比地形代码出错（4 次）还多。
> 每一次判据出错都是"**全绿**"→ 交付 → 用户一眼看出不对。

---

## 一、三层判据体系（缺一层就漏）

生成类内容的验收必须**分三层**，因为它们回答的问题不同、代价差三个数量级：

| 层 | 工具形态 | 回答什么 | 单轮代价 | 什么时候跑 |
|---|---|---|---|---|
| **① 离线纯函数** | 把几何逻辑抄成纯函数，喂假地形 | 几何**自洽**吗（层数/邻居/围死） | **秒级** | **改完几何立刻**，全绿才上世界 |
| **② 存档判据** | 读 `.mca`，按设计意图逐项验 | 真世界里**东西在不在、对不对** | 分钟级 | 生成完之后 |
| **③ 出图** | 剖面/俯视 PNG | **形态**对不对（数字绿 ≠ 形态对） | 分钟级 | 交付前最后一眼 |

### 为什么必须有 ①（离线纯函数）

生成一轮真实世界可能要 **55 分钟**。如果只靠 ②，一轮迭代 = 55 分钟。
而几何逻辑通常只依赖 `(半径, 宽度, 基准高度, 层界, 边界半径)` 这几个参数——
**完全可以离线算**。

> **凡是"改一个纯几何参数 → 生成半小时 → 看结果"的循环，都要先问：
> 这个几何能不能离线算？能就先离线，把循环从"半小时一轮"压到"3 秒一轮"。**

实测：离线自检一轮抓出 **2 个真 bug**（水悬空、沿脚横向漏），
在生成世界之前就修掉了，省掉 2 轮 × 55 分钟。

### 为什么必须有 ③（出图）

数字全在阈值内、形态却荒唐，是完全可能的。真实案例：
判据全绿（78 格水、跨度 12、厚 2），出图一看——**水在沿外面散成一条斜带**。

> **判据回答"数量对不对"，图回答"像不像"。**
> 而且用户看图 5 秒就能发现的事，判据可能 8 轮都发现不了（见盲区 #1）。

## 二、四条铁律（红线级，可脚本查）

### 铁律 1：判据和「会让它报错的样本」必须**成对存在**

只拿理想样本（好情况）去验判据，只能证明"好情况好"，
**证明不了"坏情况会被拦"**。

```
✅ 正确做法：
   [C9a] 坏样本（池内一角伸进真实洞腔）⇒ 必须复现漏（实测 512 格水 / 57 处漏）
   [C9b] 好样本（池全在真实洞腔外）  ⇒ 必须 0 漏

❌ 错误做法：
   [C9] 好样本 ⇒ 0 漏  ⇒ 打印"✔ 通过"     ← 等于没验
```

⚠️ **坏样本必须踩在判据上**。踩偏了会出现"验证通过"的假象：

> 真实翻车：造"挖空一角"的坏样本时，我改的那一格**恰好落在判据的合法区间内**
> （`{0,1}` 跨度 = 1，而阈值是"跨度 > 成员数+2"）⇒ 判"通过" ⇒ 等于没验。
>
> **修法**：坏样本要**断言它落在判据的非法侧**（比如断言 `decide(...) == False`），
> 而不是"造个看起来坏的样本，跑跑看"。

### 铁律 2：**完整性判据** —— 逐个判"已存在的元素"查不出"该存在却不存在"

> **判据按「每个已存在的元素」逐个判，就永远查不出「该存在却不存在」的元素。**

真实翻车：巨人之杯的漏水，
- `[G5]`（逐格判水会不会流）**没报**；
- `_verify_seal.py`（逐域判密封）**没报**；
- 出图**看见红点**。

为什么两个脚本都没报？因为漏法是"**池内一角整列没生成**"⇒ 那一角**压根没有水格**
⇒ "逐格判水"的脚本扫不到它（没有水格可判）。

```
❌ 物性判据（只有这一层）：for w in 所有水格: 判 w 会不会流
✅ 完整性判据（补这一层）：从水格泛洪，逃出"物件覆盖范围"即报
```

完整性判据的通用形态：**从内部出发泛洪，看能不能逃到外部**。
只要物件缺一口，泛洪必然从缺口逃出去。

### 铁律 3：按**行为规则**判，不按**存在性**判

```
❌ 判"隔壁是不是实体"（存在性）   ⇒ 把"沿外即洞腔"的正常形态全判成漏（误报 86/86）
✅ 判"水有没有地方去"（行为规则） ⇒ 原版水流规则：正下方空气 ∨ (侧邻空气 ∧ 侧邻下方也空)
```

**通用问法**：不要问"**周围是什么**"，要问"**它会不会动/会不会变**"。
把原版规则抄成判据，而不是自己发明一个相邻关系。

⚠️ 而且**改判据口径后必须双向验证**：拿改动**前**的存档跑，判据**必须报错**。
本次实测：老世界 `真会流 86/86`（证明判据会报错），新世界 `0`（证明修好了）。

### 铁律 4：边界按**最坏情况**算，并且**统计代价**

> **凡判据里出现"解析边界"（半径/圆/直线），而后面的地形是"噪声边界"，
> 就必须问：噪声把边界推出去多远？判据要按最坏情况留余量。**

真实翻车：判据写 `距离 − 半径 ≥ bore`，`bore` 是几何基准半径。
但洞腔真实外沿 = `bore` + 软化带（24）+ 噪声外凸（团块 30~50）
⇒ 实测**外扩 51 格** ⇒ 判据放行了"池内一角其实在洞腔里"的物件 ⇒ 水面缺一块 ⇒ 漏。

修法两条：
1. 判据加余量（实测外扩 51 ⇒ 取 **56**）；
2. **统计代价**：余量砍掉多少合法物件？本次实测只砍 **1.6%**（2044 → 2011），
   且全是紧贴边界的危险位 ⇒ 确认不是"为了安全把东西全砍光"。

⚠️ **余量要从实测反推，不能拍脑袋**。
本次第一次估算用"层中点"的边界值，得"只砍 1.6%"，
但真实系统用的是"物件自己那一层高度"的边界值 —— **两套口径算出的结论完全不同**，
最后是靠**用真实密度场复算**才定下来的。

## 三、已知盲区清单（踩过的，照着查）

| # | 盲区形态 | 怎么暴露的 | 修法 |
|---|---|---|---|
| 1 | **只验了 A 方向，用户要的是 B 方向**<br>（验了竖向连通，用户要横向） | 用户看图 5 秒发现，判据 8 轮没发现 | 补该方向的判据（横向泛洪） |
| 2 | **采样范围没盖住物件实际生长的地方**<br>（只扫十字带，但物件长在环带上） | 判据报"0 格水"，实际存档里有 | 判据扫描范围改成"物件的实际分布区" |
| 3 | **只判已存在元素，查不出缺失**（见铁律 2） | 逐格判据全绿，出图看见红点 | 补**完整性判据**（泛洪逃逸） |
| 4 | **数据没读到 ≠ 东西不存在**<br>（读 `.mca` 时非 full 区块返回 None → 静默跳过） | "0 个物件"，查区块状态发现只有 25% 是 `full` | 统计**扫到了多少**，低于下限就报错退出，**绝不允许"没找到就跳过"** |
| 5 | **判据口径自己改反了方向**<br>（两头都要判时只判了一头） | 生成两轮都还在漏 | 带**内边界**的合格区：不许伸出去 **且**不许探进来 |
| 6 | **泛洪/传播类判据只看直接邻居**<br>（物件有 6 格宽的围墙，水离缺口还有 6 格） | 坏样本报"0 处漏" | 改成**逐格推进**的泛洪，穿出覆盖范围才算 |

### 盲区 #4 的硬性写法（容易忘，但很致命）

```python
# ❌ 静默跳过 —— "没找到"和"不存在"分不开
for c in candidates:
    data = read(c)
    if data is None:
        continue

# ✅ 统计扫到的数量，不够就报错退出
scanned = 0
for c in candidates:
    data = read(c)
    if data is None:
        continue
    scanned += 1
if scanned < MIN_EXPECTED:
    raise SystemExit(f'只扫到 {scanned} 个（下限 {MIN_EXPECTED}）—— 判据结果不可信')
```

**推广**：凡是"扫目录/扫范围"的判据，都要**返回它扫到了多少条目**，
调用方见 0（或低于下限）**必须报错退出**，绝不允许"没找到就跳过"。
路径参数也要**相对基准目录优先解析 + 找不到就明确报错**。

## 四、操作级：怎么写一条可用的判据

### 模板

```python
def 判据名(对象) -> list[str]:
    """返回错误列表；空列表 = 通过。

    ⚠️ 每条错误要带上**能定位的坐标**，不要只说"不合格"。
    """
    errs = []
    # 1) 先做**前置检查**：数据读到了吗？数量够吗？（防线 4）
    if 对象.数量 == 0:
        return ['[前置] 一个都没扫到 —— 结果不可信，先查数据源']
    # 2) 主判据
    for 元素 in 对象:
        if 违反(元素):
            errs.append(f'[{判据号}] ({元素.x},{元素.y},{元素.z}) 具体原因')
    # 3) 完整性判据（防线 2）
    if 泛洪逃逸(对象):
        errs.append('[完整性] 泛洪逃出覆盖范围 —— 有缺口')
    return errs
```

### 成对写法（好坏例）

```
坏例：assert 水格数 > 0
      为什么坏：只要有一格水就过，缺口/悬空/阶梯水全查不出来
好例：assert 水只有 1 层      # 阶梯水的特征就是"水有十几层"
      assert 每个水格正下方是实体
      assert 每个水格正上方是盖板

坏例：[C6] 盘子不许伸出洞腔（只判一头）
      为什么坏：另一头静默失效，允许往洞里探
好例：cdist − rr − 沿宽 ≥ 洞腔半径 + 噪声余量   # 整盘在洞腔之外

坏例：坏样本"造个看起来坏的"，跑出来看结果
      为什么坏：可能恰好落在判据的合法区间 ⇒ 假通过
好例：坏样本 + 断言它落在非法侧（assert decide(...) is False）
      好样本 + 断言它落在合法侧
```

## 五、判据自己的自检流程（交付前跑一遍）

```
1. 判据**能报错**吗？       → 拿"已知坏的"输入跑，必须报红        （铁律 1 / 3）
2. 判据**报得准**吗？       → 拿"已知好的"输入跑，必须全绿、0 误杀
3. 判据**看得见数据**吗？   → 打印"扫到了多少条目"，确认 > 下限    （盲区 2 / 4）
4. 判据**覆盖对方向**吗？   → 逐条列出"这个判据验的是哪个方向/哪一层"（盲区 1）
5. 判据**有完整性项**吗？   → 除了"每个东西好不好"，有没有"该有的在不在"（铁律 2）
```

第 3、5 条最常被漏。它们不会让判据报错，只会让判据**安静地全绿**。

## 六、反面教材：本项目判据翻车 5 次全记录

| 次 | 判据 | 错误结论 | 真相 | 根因 |
|---|---|---|---|---|
| 1 | 竖向连通判据 | 全绿 | 横向被一圈完整环墙隔断 | 验的方向❌（盲区 1） |
| 2 | 巨人之杯采样 | "0 格水" | 杯子在环带上，判据只扫十字带 | 采样范围❌（盲区 2） |
| 3 | 密封判据 | "86 域全有漏点" | 判"四邻有实体"⇒ 把正常形态误报 | 口径❌（铁律 3） |
| 4 | 密封判据 / 逐格水流 | "全绿" | 池内一角整列没生成，没水格可判 | 缺完整性（铁律 2） |
| 5 | 水位判据 | "第 4 层 0 格水" | 只有 25% 区块是 `full`，其余被静默跳过 | 数据没读到（盲区 4） |

**五次里有四次是"判据结果全绿/全红但不作数"，一次是"验错方向"。**

> ⭐ **最重要的一条认知**：
> **判据变绿不是"没问题"，只是"这个判据没发现问题"。**
> 每次判据给了反直觉的结果（全绿或全红），先怀疑判据，再怀疑被测对象。

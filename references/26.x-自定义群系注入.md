# 26.x 给主世界加自定义群系（唯一的正确路子 + 全部踩坑）

> 实测版本：**MC 26.1.2 / NeoForge 26.1.2.108 / Java 25**。工作产物见工作区 `Lumenwild` 工程。
> 下面每一句都是实机跑出来的，不是推演。

---

## 0. 结论先行

**26.1 起，「往主世界塞一个新群系」只剩 Mixin 一条路**，而且必须用「**接管宿主群系的参数表条目**」的写法。
任何"追加新条目"的思路都会失败，而且**失败得悄无声息**（`possibleBiomes()` 照样返回 true，
不采样根本发现不了）。

---

## 1. 为什么数据包和 biome modifier 都不行

### 1.1 数据包这条路已经堵死

26.1 起 `data/minecraft/worldgen/multi_noise_biome_source_parameter_list/overworld.json`
的内容是**完整的一句话**：

```json
{
  "preset": "minecraft:overworld"
}
```

真正的参数表（26.1.2 里是 **7593 组**「气候参数 → 群系」）被硬编码进
`net.minecraft.world.level.biome.MultiNoiseBiomeSourceParameterList$Preset` 的
`generateOverworldBiomes(Function)` 静态方法里。

`MultiNoiseBiomeSourceParameterList.DIRECT_CODEC` 是 `record(preset, parameters)`，
其中 `parameters` **不参与序列化**（由 preset 在构造时重算）。
所以你在数据包里写这个文件只能填一个内置 preset 名（`minecraft:overworld` / `minecraft:nether`），
**没有任何语法能往里追加条目**。

> 顺带一个坑：`Preset.CODEC` 是 `Identifier -> BY_NAME` 查表，
> `BY_NAME` 是 `Preset` 静态实例构成的 `Map`，跑起来之后也加不进新东西。

### 1.2 NeoForge 的 biome modifier 也不行

`net.neoforged.neoforge.common.world.BiomeModifiers` 里一共 8 种类型（26.2 逐个数过）：

```
AddCarvers / RemoveCarvers / AddFeatures / RemoveFeatures
AddSpawns / RemoveSpawns / AddSpawnCosts / RemoveSpawnCosts
```

**没有 add_biomes。** 它们全部作用于「已经存在的群系」，没有任何一种能让新群系进入世界。

所以"加矿石、加刷怪、加植被"可以纯数据包搞定；"加群系"不行。

## 2. 正确做法：Mixin 改参数表，且必须「接管」而不是「追加」

### 2.1 注入点

目标是 `MultiNoiseBiomeSourceParameterList$Preset` 的
`private static <T> Climate.ParameterList<T> generateOverworldBiomes(Function<ResourceKey<Biome>, T>)`。

它在两条路径上被调用，**两条都要管**：

| 路径 | 转换函数 | 元素类型 T | 发生时机 |
|---|---|---|---|
| 引导 `Preset.knownPresets()` | `Function.identity()` | `ResourceKey<Biome>` | 注册表 bootstrap / 命令校验 |
| 运行 `MultiNoiseBiomeSourceParameterList(Preset, HolderGetter)` | `biomeGetter::getOrThrow` | `Holder.Reference<Biome>` | 从数据包 `{"preset": ...}` 构造时 |

所以判断"这条是不是宿主"要**两种类型都认**（`Holder#unwrapKey()` 或直接比 `ResourceKey`）。

### 2.2 🔴 为什么必须「接管」：fitness 并列陷阱

`Climate.ParameterPoint.fitness()`（字节码核对过）：

```
fitness = square(dist_temp) + square(dist_humid) + square(dist_cont)
        + square(dist_erosion) + square(dist_depth) + square(dist_weird)
        + square(offset)                        ← 注意是 offset 的平方
```

* `distance` 是「目标点到参数**区间**的距离」——**落在区间内就是 0**。
* 只要两个条目的参数区间都包含同一个目标点，两边距离项全是 0，**只能比 `square(offset)`**。
* `offset` 是 `long`，平方恒 ≥ 0，**最小值就是 0**（负数会变大，别想用负 offset 提优先级）。

而原版那 7593 条参数表本身就是把气候空间**铺满并划分**开的（同一群系往往有上百条相邻条目
做平滑过渡 —— 实测深色森林有 **172 条**）。你追加进去的条目不管把参数怎么"内缩"，
永远和某个原版条目共处同一片区域，只能靠 offset 决胜，而 offset 并列时胜负取决于
`Climate.RTree` 的遍历顺序 —— **追加在列表末尾，基本等于永远轮不到**。

**实测数据（±2000 格地表网格 15876 个采样点）**：

| 写法 | 幽荧林地占比 |
|---|---|
| 追加（参数 = 宿主内缩 10%，宿主 offset +1） | **0.00%** ← 一个都没生成 |
| 追加（干脆用宿主的参数点原样追加） | 0.00% |

**正确写法是就地替换**：找到原本指向宿主群系的条目，**参数点原封不动**，只把指向的群系换掉。
原版参数点是精心调过的，接管过来就是**独占**那片气候区，不存在并列。

### 2.3 接管多少条：按比例调，别全接管

同一个宿主群系有几十上百条条目，全接管会把宿主**从主世界彻底抹掉**。
实测（同上采样口径，宿主 = 深色森林，共 172 条）：

| 接管条目 | 新群系占比 | 宿主占比 |
|---|---|---|
| 172/172（全部） | 1.97% | **0.00%**（原版群系消失） |
| 86/172（每 2 条接手 1 条） | 1.97% | 0.00% |
| **43/172（每 4 条接手 1 条）** | **0.96%** | **1.01%** ← 推荐 |

注意第二行：接管一半时新群系占比**没有减半**，说明原版那 172 条里有一半是"影子条目"
（从不获胜）。所以**别凭条数比例去估地盘，一定要跑一次采样量一下**。
「每 4 条接手 1 条」这个比例在两个不同群系上都测出了"各占一半气候带"的效果，可以当起点。

### 2.4 代码骨架

```java
@Mixin(MultiNoiseBiomeSourceParameterList.Preset.class)
public abstract class MyPresetMixin {

    @Inject(method = "generateOverworldBiomes", at = @At("RETURN"), cancellable = true)
    private static <T> void mymod$takeOverHost(Function<ResourceKey<Biome>, T> lookup,
                                              CallbackInfoReturnable<Climate.ParameterList<T>> cir) {
        Climate.ParameterList<T> original = cir.getReturnValue();
        if (original == null) return;

        final T ourEntry;
        try {
            ourEntry = lookup.apply(MyBiomes.MY_BIOME);      // 群系没注册时会抛，务必兜住
        } catch (RuntimeException ex) {
            return;
        }

        List<Pair<Climate.ParameterPoint, T>> values = new ArrayList<>(original.values());
        int taken = 0, seen = 0;
        for (int i = 0; i < values.size(); i++) {
            Pair<Climate.ParameterPoint, T> e = values.get(i);
            if (!isHost(e.getSecond())) continue;
            seen++;
            if (seen % 4 != 1) continue;                     // 每 4 条接手 1 条
            values.set(i, Pair.of(e.getFirst(), ourEntry));   // ⚠️ 参数点原样保留
            taken++;
        }
        if (taken == 0) {                                     // 没找到宿主 → 兜底
            values.add(Pair.of(FALLBACK_POINT, ourEntry));
        }
        cir.setReturnValue(new Climate.ParameterList<>(values));
    }

    @Inject(method = "usedBiomes", at = @At("RETURN"), cancellable = true)
    private void mymod$addUsedBiome(CallbackInfoReturnable<Stream<ResourceKey<Biome>>> cir) {
        cir.setReturnValue(Stream.concat(cir.getReturnValue(), Stream.of(MyBiomes.MY_BIOME)));
    }

    @SuppressWarnings({"unchecked", "rawtypes"})
    private static boolean isHost(Object value) {
        if (value instanceof Holder holder) {                 // 运行路径：Holder.Reference
            Optional<ResourceKey<Biome>> k = holder.unwrapKey();
            return k.isPresent() && k.get().equals(MyBiomes.HOST);
        }
        return MyBiomes.HOST.equals(value);                   // 引导路径：ResourceKey
    }
}
```

配套 `src/main/resources/mymod.mixins.json`：

```json
{
  "required": true,
  "minVersion": "0.8",
  "package": "com.example.mymod.mixin",
  "compatibilityLevel": "JAVA_25",
  "mixins": ["MyPresetMixin", "RegistrySetBuilderBuildStateMixin"],
  "injectors": { "defaultRequire": 1 }
}
```

并在 `neoforge.mods.toml` 里声明（26.x 模板里这段是注释状态，取消注释即可）：

```toml
[[mixins]]
config="${mod_id}.mixins.json"
```

`compatibilityLevel` 26.x 用 `JAVA_25`（1.20.1 只能到 `JAVA_17`，写高了会在初始化阶段直接崩且不生成崩溃报告）。

## 3. 🔴 第二个必修的坑：`Unreferenced key` 校验

只做第 2 节那一个注入的话，**服务端启动会直接挂**：

```
java.lang.IllegalStateException: Errors during registry creation
    at net.minecraft.data.registries.VanillaRegistries.createLookup(VanillaRegistries.java:142)
    at net.minecraft.commands.Commands.validate(Commands.java:537)
    at net.minecraft.server.Bootstrap.validate(Bootstrap.java:124)
Suppressed: java.lang.IllegalStateException: Unreferenced key: ResourceKey[minecraft:worldgen/biome / mymod:my_biome]
    at RegistrySetBuilder$BuildState.reportNotCollectedHolders(RegistrySetBuilder.java:297)
```

**原因**：26.x 的 `RegistrySetBuilder.BuildState` 构建完数据包注册表后会跑 `reportNotCollectedHolders()`，
遍历 `UniversalLookup.holders`（= **已创建但从未被 get 出来的 LazyHolder**），
剩下的每一个都判 `Unreferenced key` 并抛错。

原版群系不在这张名单里，因为它们被 `MultiNoiseBiomeSourceParameterList` 解析过。
但那条链路在**引导阶段**走的是 `knownPresets()` + `Function.identity()`，**不产生任何 Holder 解析**；
只有运行路径（`biomeGetter::getOrThrow`）才会真正解析。
于是我们用 Mixin 塞进去的群系成了「注册了但没人解析」的孤儿。

**试过但没用**的写法：在 `MultiNoiseBiomeSourceParameterLists.bootstrap` 的 TAIL 里
`context.lookup(Registries.BIOME).get(key)` —— bootstrap 阶段拿到的 lookup 看不到该 key，
不产生 resolve 记录。这条路别浪费时间。

**有效解法**：在校验开始前把 key 从"未解析名单"里摘掉。校验方法在
`net.minecraft.core.RegistrySetBuilder$BuildState`（包私有内部类，用 `@Mixin(targets = "...")`）：

```java
@Mixin(targets = "net.minecraft.core.RegistrySetBuilder$BuildState")
public abstract class RegistrySetBuilderBuildStateMixin {

    @Inject(method = "reportNotCollectedHolders", at = @At("HEAD"))
    private void mymod$markResolved(CallbackInfo ci) {
        try {
            Field lookupField = this.getClass().getDeclaredField("lookup");   // BuildState.lookup
            lookupField.setAccessible(true);
            Object lookup = lookupField.get(this);
            Field holdersField = lookup.getClass().getDeclaredField("holders"); // UniversalLookup.holders
            holdersField.setAccessible(true);
            Object holders = holdersField.get(lookup);
            if (holders instanceof Map<?, ?> map) {
                map.keySet().removeIf(MyBiomes.MY_BIOME::equals);
            }
        } catch (Throwable t) {
            // 反射失败不该拖垮启动，让原版校验照常报错
        }
    }
}
```

`holders` 的 key 是 `ResourceKey<?>`，`removeIf` 直接比 key 即可。
**只摘自己的 key**，别的 mod 有同样毛病照样被原版校验抓出来。

## 4. 26.1 的 biome JSON 结构变化（写群系 JSON 前必看）

26.1 引入了 environment attributes 体系，`biome` 的 schema 跟着变了：

```json
{
  "attributes": {                          // ★ 新段：原 sky_color / fog_color / music 都搬这儿
    "minecraft:visual/sky_color": "#5f9f96",
    "minecraft:visual/fog_color": "#2f4f4a",
    "minecraft:visual/water_fog_color": "#1d4d44",
    "minecraft:audio/background_music": {
      "default": { "max_delay": 24000, "min_delay": 12000, "sound": "minecraft:music.overworld.forest" }
    }
  },
  "effects": {                             // 只剩这几个
    "water_color": "#2f8f7a",
    "grass_color": "#4fb07f",
    "foliage_color": "#3f8a63",
    "dry_foliage_color": "#6b5a34"
  },
  "has_precipitation": true,
  "temperature": 0.6,
  "downfall": 0.9,
  "carvers": ["minecraft:cave", "minecraft:cave_extra_underground", "minecraft:canyon"],
  "features": [ [/*0 RAW_GENERATION*/], [/*1 LAKES*/],
                [/*2 LOCAL_MODIFICATIONS*/], [/*3 UNDERGROUND_STRUCTURES*/],
                [/*4 SURFACE_STRUCTURES*/], [/*5*/],
                [/*6 原版的矿 + disk 都塞在这层*/], [/*7 FLUID_SPRINGS*/],
                [/*8 VEGETAL_DECORATION*/], [/*9 TOP_LAYER_MODIFICATION*/] ],
  "spawn_costs": {},
  "spawners": { /* ↓ 见下 */ }
}
```

### 4.1 `attributes` 里的可用 id（从 `EnvironmentAttributes` 常量池抠出来的）

前缀只有三种：`visual/` `audio/` `gameplay/`。视觉类常用的：

```
visual/sky_color  visual/fog_color  visual/water_fog_color
visual/fog_start_distance  visual/fog_end_distance
visual/sunrise_sunset_color  visual/cloud_color  visual/cloud_height
visual/ambient_light_color  visual/night_vision_color  visual/sky_light_color
visual/star_brightness  visual/moon_phase  visual/ambient_particles
audio/background_music  audio/music_volume  audio/ambient_sounds
gameplay/monsters_burn  gameplay/water_evaporates  gameplay/fast_lava  gameplay/bed_rule  ...
```

颜色写 `"#rrggbb"`。**别写 `effects.sky_color` 之类的老字段** —— 26.1 起不认，会解析失败。

### 4.2 `spawners` 现在是**对象数组**，不是 id 列表

```json
"spawners": {
  "ambient":   [ { "type": "minecraft:bat", "minCount": 8, "maxCount": 8, "weight": 10 } ],
  "axolotls":  [],
  "creature":  [ { "type": "minecraft:sheep", "minCount": 4, "maxCount": 4, "weight": 12 } ],
  "misc":      [],
  "monster":   [ { "type": "mymod:my_mob", "minCount": 1, "maxCount": 3, "weight": 120 } ],
  "underground_water_creature": [ { "type": "minecraft:glow_squid", "minCount": 4, "maxCount": 6, "weight": 10 } ],
  "water_ambient": [],
  "water_creature": []
}
```

写成一串 id（`["minecraft:bat"]`）会报
`MobSpawnSettings: Spawn data: Not a JSON object: "minecraft:bat"`，并且**该群系整个加载失败**
（然后你可能又撞上第 3 节的 Unreferenced key —— 因为群系根本没注册成功）。
`MobSpawnSettings$SpawnerData` 是 `record(EntityType type, int minCount, int maxCount)`，
weight 来自外层的 `WeightedList`。

### 4.3 地表方块怎么换

群系 JSON **管不了地表**（surface rule 在世界预设里，改不了）。
给自定义区块铺自己的地表方块用 `minecraft:disk` 特征（原版 clay/sand disk 同款）：

```json
// configured_feature/my_soil_disk.json
{ "type": "minecraft:disk",
  "config": { "half_height": 2,
      "radius": { "type": "minecraft:uniform", "min_inclusive": 3, "max_inclusive": 7 },
      "state_provider": { "type": "minecraft:simple_state_provider",
                          "state": { "Name": "mymod:my_soil" } },
      "target": { "type": "minecraft:matching_blocks",
                  "blocks": ["minecraft:dirt","minecraft:grass_block","minecraft:podzle"] } } }
```

⚠️ 注意方块状态引用是 NBT 风格的 `{"Name": "..."}`（26.1 仍未改）。
再配一个 placed_feature（`count` + `in_square` + `heightmap` + **`biome`** 四步，
最后那步 `minecraft:biome` 不能漏，否则会在别的群系也铺）。
两层 disk（先铺土、再把它换成苔）就能做出"贴地苔毯"的近似效果。

## 5. 验证：怎么确定它真的会生成

### 5.1 ❌ 别用 `findBiomeHorizontal` 去"定位"

`BiomeSource.findBiomeHorizontal(...)` 就是 `/locate biome` 走的方法，
**它会真的去生成/扫描区块**。在 `ServerStartedEvent` 里（服务端主线程）跑一次 6400 格搜索，
实测直接把 tick 卡过 60 秒：

```
[Server Watchdog/ERROR]: A single server tick took 60.00 seconds (should be max 0.05)
[Server Watchdog/ERROR]: Considering it to be crashed, server will forcibly shutdown.
```

`/locate biome` 本身没问题（那条命令在正常的 tick 流程里跑），**只是别在启动事件里调它**。

### 5.2 ✅ 用纯气候采样（毫秒级，不加载区块）

```java
ServerLevel overworld = server.overworld();
BiomeSource source = overworld.getChunkSource().getGenerator().getBiomeSource();
Climate.Sampler sampler = overworld.getChunkSource().randomState().sampler();   // 26.1 的取法

int hit = 0, total = 0;
for (int x = -2000; x <= 2000; x += 32) {
    for (int z = -2000; z <= 2000; z += 32) {
        Holder<Biome> b = source.getNoiseBiome(x >> 2, 16, z >> 2, sampler);    // 参数是 quart 坐标
        total++;
        if (b.unwrapKey().map(k -> k.equals(MY_BIOME)).orElse(false)) hit++;
    }
}
LOGGER.info("占比 {}%", hit * 100.0 / total);
```

顺便**统计 top 群系分布**，一眼就能看出问题：
* 全是 `ocean` / `caves` → y 参数取错（`getNoiseBiome` 的 y 是 quart，地表取 16）；
* 新群系 0 命中但 `possibleBiomes()` 里有 → 就是第 2.2 节的并列问题；
* 宿主群系也 0 → 接管过头了。

> 26.1 里 `ChunkGenerator` **没有** `climateSampler()` 方法了，别照抄老代码。
> sampler 从 `ServerChunkCache#randomState()` → `RandomState#sampler()` 取。

### 5.3 只查 `possibleBiomes()` 会骗你

`MultiNoiseBiomeSource.collectPossibleBiomes()` 是
`parameters().values().stream().map(Pair::getSecond)` ——
**只要条目在表里就返回 true**，哪怕它永远选不中。
所以 `possibleBiomes().contains(myBiome) == true` **不能**证明群系会出现，必须跑采样。

## 6. 排查清单（按症状查）

| 症状 | 原因 | 处理 |
|---|---|---|
| 启动 `Unreferenced key` | 引导阶段不产生 Holder 引用 | 加第 3 节的 `RegistrySetBuilderBuildStateMixin` |
| 启动 `Mod xxx requires minecraft 26.1` | `minecraft_version_range=[26.1]` 是精确匹配，实际是 26.1.2 | 改成 `[26.1,26.2)` |
| 启动 `MixinInitialisationError: ... JAVA_xx not recognised` | `compatibilityLevel` 写太高（且不生成崩溃报告） | 26.x 用 `JAVA_25`，1.20.1 最高 `JAVA_17` |
| 群系在 `possibleBiomes()` 里但一个不生成 | 用了"追加"而不是"接管"（fitness 并列） | 改成接管宿主条目 |
| `MobSpawnSettings: Spawn data: Not a JSON object` | `spawners` 写成 id 数组 | 改成对象数组（type/minCount/maxCount/weight） |
| 群系 JSON 解析失败、字段不认 | 用了 1.21 的 `effects.sky_color` 老写法 | 搬到 `attributes` 段的 `minecraft:visual/...` |
| 服务器启动卡死 60 秒被判崩 | 在启动事件里调了 `findBiomeHorizontal` | 改纯采样（第 5.2 节） |
| 第二次 `runServer` 报 `FAILED TO BIND TO PORT` | 上一次的服务端 java 进程没退（尤其被信号打断） | 杀命令行含 `devlaunch` 的 java 进程 |
| 新群系把原版群系吃没了 | 接管了全部条目 | 按比例接管（每 4 条 1 条起），并采样核对两边占比 |

## 7. 交付前的最低验证标准

1. `gradlew build` 通过；
2. `gradlew runServer` 能到 `Done (x.xxs)!`，且日志里没有 `Unreferenced` / `Not a JSON` / `crash-report`；
3. 自检日志里 **新群系采样占比 > 0**，同时宿主群系占比也 > 0（说明没把原版群系吃没）；
4. 进游戏 `/locate biome <ns>:<biome>` 能定位到，实际走一圈看观感。

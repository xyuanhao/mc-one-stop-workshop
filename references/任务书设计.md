# 任务书设计指南（内容层）

> **分工**：本文只回答「**任务该写什么**」。
> 字段/语法/文件路径 → `FTB_Quests任务编辑.md`（≤1.21.x 的 SNBT）；26.1.2+ 的 JSON5 + lang 文本表 → `SKILL.md` 对应两节。
>
> **两条不可协商的硬指标**（写在最前面，因为大多数整合包在这里翻车）：

| # | 指标 | 判据 | 怎么证 |
|---|---|---|---|
| 1 | **覆盖度 100%** | `mods/` 里每个**内容模组**都在任务书里出现过至少一次 | `scripts/任务书覆盖度.py <实例>`（退出码 1 = 有模组零提及） |
| 2 | **循序渐进** | 每个任务都有前置；阶段门槛单调递进；不存在"先去末地再给你木镐" | 阶段表 + 依赖链回溯（§2） |

**装了一个模组，玩家在任务书里一个字都看不到 = 白装。** 这是整合包最常见也最致命的设计缺陷：
作者自己知道有这个 mod，玩家不知道，于是整包装了 150 个 mod 玩起来像装了 15 个。

---

## 1. 覆盖度：把每一个模组都排进任务书

### 1.1 第一步不是写任务，是出「覆盖矩阵」

拿 `mods/` 目录（或模组清单 JSON）当输入，逐个 modid 过一遍，填这张表——**填完才动笔**。

| 类别 | 典型识别特征 | 任务化方式 | 落点强度 |
|---|---|---|---|
| **基础库 / 前置** | 无自己的物品方块（Architectury / Cloth Config / Balm / JEI / Curios） | 不单独开任务。写在所属章节 `description` 的「本章用到」一行 + 给个图标 | 弱（提及即可） |
| **生存增强 / QoL** | Jade、AppleSkin、旅行地图、背包、整理 | **P0 开局引导任务**（checkmark）：教按键、教用法 | 中（一个开局任务） |
| **存储与物流** | Sophisticated Storage、Tom's Storage、Pipez、抽屉 | 各自 1-3 个任务：做出第一个 → 升级 → 成规模 | 强（成链） |
| **科技 / 机械** | Create、Mekanism、AE2、Powah、IE | **独立章节**，按机器/产线递进（见 §1.2 蓝图） | 强（整章） |
| **魔法 / 进度线** | 灵灾型、植物魔法型、Iron's Spells 型 | **独立章节**，按等级/阶位递进 | 强（整章） |
| **探索 / 世界生成** | YUNG's 系列、结构 mod、群系 mod、地牢 | **探索章节**：`structure` / `biome` / `dimension` 任务；YUNG's 是替换原版结构 → **用原版结构 id** | 中（按区域分条） |
| **战斗 / 怪物** | 怪物增强、Boss 扩展 | **战斗章节**：`kill` 任务 + 图鉴式条目（每个 Boss 一条） | 中 |
| **装饰 / 生活** | 家具、画、Macaw 系列、食物扩展 | 归「生活」支线，**可选任务**（`optional: true`） | 中（支线章） |
| **纯兼容/数据包** | 无 jar 或空壳 | 不落点，README 里说明 | 无 |

**分类不用纠结，落到"能写任务"就行**。判断口诀：**它给玩家的是"一个新东西"还是"一个新玩法"？**
新东西 → 独立任务；新玩法 → 独立章节。

### 1.2 覆盖度怎么自查（写完必跑）

```bash
python scripts/任务书覆盖度.py "<实例目录>"              # 自动找 mods/ 与 config/ftbquests/
python scripts/任务书覆盖度.py <实例> --strict           # 库/QoL 零提及也算失败
python scripts/任务书覆盖度.py <实例> --md 覆盖率.md      # 出报告文件
```

> ⚠️ **有 `mods/` 时脚本优先读 jar，`--modlist` 会被忽略**（`--modlist` 只在没有 jar 的纯清单场景用）。
> 所以对着实例跑就行，不用另外喂清单；报告头部的「模组来源」会告诉你它实际读的是什么。

它读 `mods/*.jar` 的 modId、扫任务书所有文件（含 `lang/*.json5`，SNBT 与 JSON5 都认）里的
`namespace:path` 引用，两边对账。**模组按「内容模组 / 库·QoL」自动分层**
（看 jar 里有没有自己的方块/物品贴图/配方/群系资源，带数量阈值防误判），只有内容模组零提及才置退出码 1。

报告分四块：

| 段落 | 含义 | 处置 |
|---|---|---|
| ❌ 内容模组零提及 | 有玩法却没进任务书 —— **真问题** | 按 §1.1 补落点（开章节或最少一条任务） |
| ○ 库/QoL 零提及 | 无自己玩法，玩家也不知道怎么用 | 建议在 P0 加一个「这包有什么」任务按类列一遍；`--strict` 时升级为失败 |
| ○ 仅文本提及 | 只在描述里写了 modid，没有任务真正用到 | 库这样够了；**内容模组停在这一档 = 玩法没进流程** |
| B. 反查：任务书引用了但 mods 里没有 | id 拼错 / mod 已移除没同步 | id 拼错 → 任务**永远做不了**且不报错，必须修 |

**两个已知局限**：
- **中文译名识别不了**（写「机械动力」而不写 `create` 就等于没提及）→ 所以规范是：描述里带上 modid 原文，
  玩家也能搜得到。
- 内容/库分层是**启发式**，判错了人工忽略即可（`--strict` 只在你确定分层准确时用）。

#### 🔴 颜色码陷阱（2026-09-13 实测踩坑，已在脚本内修复）

FTB 任务书描述里几乎每行都带颜色码（`&7` `&e` `&8`…）。**颜色码紧贴 modid 时会让词边界匹配失效**：

```
"&8alexsmobs&7 ..."     ← 期望命中 alexsmobs，实际漏判
```

原因：脚本原先的前边界是 `(?<![A-Za-z0-9_\-])`，而 `&8` 里的 **`8` 本身属于 `[A-Za-z0-9]`**
（`&e` `&a` `&f` 同理，字母也是），于是 `8alexsmobs` 被当成一个整体词，modid 前边界不成立。

**修法（已在 `scripts/任务书覆盖度.py` 落实）**：匹配前先剥颜色码。

```python
plain = re.sub(r"[&§][0-9a-fk-orx]", " ", all_text, flags=re.I)
```

**写文案时的自保习惯**（双保险，改了脚本也别丢）：
- modid 前**加一个空格**：`&8 alexsmobs` 不如直接 `&7- &eAlex's Mobs&7（alexsmobs）：…` 这种「展示名 + 括号 modid」写法最稳
- **不要**写 `&8modid`、`&emodid` 这种颜色码直贴的形态

> 影响量级：修前 79.7% → 修后 95.3%（同一个包、同一批文案）。**这是"明明写了却报零提及"的最常见原因**，
> 遇到假阴性先查这里，别急着改文案。

#### 🔴 幽灵 modId：平台元数据 + 注释段（2026-09-13 实测，已在脚本内修复）

覆盖度对不上时，**先怀疑"读到的 modId 是不是真的存在"**，再怀疑文案。两类来源会让脚本凭空多出 modId：

**① 同一个 jar 带多家平台元数据，脚本全收了**

有些 jar 同时有 `META-INF/*.mods.toml`（Forge/NeoForge）和 `fabric.mod.json`（Fabric），
**两边声明的 modId 可能不一样**。实测：

| jar | toml 的 modId | fabric 的 modId | 后果 |
|---|---|---|---|
| `HopoBetterRuinedPortals` | `hoporp` ✅ | `hopobetterruinedportal` | 多一个永不命中的假 id |
| `entity_texture_features` | `entity_texture_features` ✅ | `neoforge` | 把加载器名当成了 modId，污染更重 |

修法：**只要读到了 toml 就不再认 fabric**（本工具主战场是 NeoForge/Forge）。

**② 被注释掉的段头把 `dependencies` 的 modId 混进来**

```
#[[dependencies.entity_texture_features]]
#modId = "neoforge"          ← 整段被注释，但脚本按行首 [[ 切段时归到了下一个真实段
[[dependencies.entity_texture_features]]
modId = "minecraft"
```

修法：段头含 `#` 直接跳过；段体里逐行剔掉 `#` 开头的注释行再正则。

**为什么必须修**：幽灵 id 永远不可能被任务书"提及" → **覆盖率被永久压低**，
还会被误报成「内容模组零提及」，逼你去给一个不存在的 mod 写任务。
实测远境：修前报 1 个假零提及（`hopobetterruinedportal`），修后 **58/58 全绿**；
报告 B 段原本 20 条"引用了但 mods 里没有"的假警报也一并消失。

**自查口诀**：报「零提及」时，先把那个 modId 拿去 `mods/*.jar` 里搜一遍 ——
**jar 里搜不到 = 不是文案的问题，是脚本读错了**。

**覆盖度是必要条件，不是充分条件**：提到了 ≠ 讲清楚了。达标线是
**"玩家只看任务书，能大致搞明白这个 mod 是干嘛的、第一步做什么"**。

> 真实基线（2026-09-13 实测两个自建包）：机械动力包 51 个内容模组，任务书只提到 2 个（2.4%）；
> 26.1 的「远境」5 个内容模组提到 1 个。**"只写主线"是默认结果，不是极端情况**——所以这个检查必须跑。

## 2. 循序渐进：阶段划分与门槛

### 2.1 四阶段骨架（几乎所有整合包都能套）

| 阶段 | 时长占比 | 玩家状态 | 目标 | 门槛物（该阶段标志） |
|---|---|---|---|---|
| **P0 落地** | 10-15% | 一无所有 | 教会操作 + 告知这包有什么（QoL 任务、图鉴引言） | 石镐 / 木镐 |
| **P1 立足** | 20-25% | 有家、有铁 | 建立基地、第一条产线、存储 | 铁锭 + 熔炉 / 基础存储 |
| **P2 分线** | 40-50% | 有余力 | **科技 / 魔法 / 探索 三线并行**（玩家自选先后） | 该线的一阶产物（钢、能量单元、附魔装备） |
| **P3 终局** | 20-25% | 熟练 | 每线的高端目标 + **跨线联动**（科技产物喂魔法线之类） | 各线终局物品 |

**硬规则**：

1. **每条任务链都能从 P0 起点回溯到**（无孤儿节点）。写完用 `任务书覆盖度.py` 的**断链检查**（`--chain`）过一遍。
2. **不允许跳阶段**：P3 任务的依赖必须穿过 P2、P1，不能直接挂在起点上。
3. **门槛物出现在它该出现的阶段**：P1 的任务里出现"下界合金"就是设计事故。
4. **并行宽度随阶段增加**：P0 一条线 → P1 两三条 → P2 三线并行 → P3 收敛回里程碑。
5. **每阶段收尾放一个里程碑任务**（`shape: "diamond"` 或 `"pentagon"`）：它是下一阶段的钥匙，也是奖励最厚的地方。

### 2.2 布局（x/y 网格）

- 一条链：**x 相同，y 每步 1.5~2.0 格**往下排（FTB 默认从上往下解锁）。
- 分线：从里程碑任务**向右扇形展开**，每条线的 x 递增一个固定步长（如 4 格），别交叉。
- 阶段之间：留一个明显的**横向空档**（视觉上能看出"翻页了"）。
- 坐标只是示意，最终进游戏用 `/ftbquests editing_mode` 拖——**别把时间花在手写坐标上**。

## 3. 详细度三档（任务文案写多少）

> 三档是**每任务描述长度**的档位，可全局统一，**也推荐按阶段下调**（P0 高 → P3 低，因为玩家越来越熟）。

| 档 | 定位 | 单个任务描述 | 章节引言 | 奖励并置 |
|---|---|---|---|---|
| **低** | 速通 / 硬核 / 老玩家 / 纯 grind | **0-1 行，≤40 字**：目标 + 关键提示 | 无，或 1 行 | 通常配低奖励档 |
| **中（默认）** | 大多数整合包 | **2-4 行，60-150 字**：目标 → 步骤 → 注意点 | 3-5 行：本章解决什么问题 | 通常配中奖励档 |
| **高** | 剧情向 / 教学向 / 玩家没接触过该 mod | **6-15 行，200-500 字**：设定/背景 → 分步 → 常见坑 → 与其他线的联动 | 整章引言（可 `{@pagebreak}`） | 通常配高奖励档 |

### 3.1 同一任务的三种写法（以「做出第一个石炭熔炉」为例）

**❌ 坏例（低档但写成了废话）**
```
"&7做出一个熔炉吧。"
```
问题：没说为什么、没说材料从哪来、没提示 mod 特有的坑 → **玩家卡住**。低档 ≠ 敷衍。

**✅ 低档**
```
"&7目标：&e石炭熔炉 &7× 1&r\\n&8提示：石炭打圆石出，别用手挖。"
```
一行给全「做什么 + 唯一关键点」。

**✅ 中档**
```
"&7目标：做出第一个 &e石炭熔炉&7。\\n\\n"
"&7① 挖 8 个圆石，用石炭在熔炉里烧出石灰石粉\\n"
"&7② 工作台合成炉芯\\n"
"&7③ 右键放置，注意只能放平地上"
```
目标 → 三步 → 一句坑。

**✅ 高档**
```
"&6【第一章 · 第一节】\\n&7"
"你醒来时，背包里只有半块面包和一把生锈的镐子。\\n"
"&7远处有炊烟——但那不是人。\\n\\n"
"&e目标：&7做出一个 &e石炭熔炉&7，它能烧出比木头热三倍的火焰。\\n\\n"
"&7① 木镐挖 8 圆石（别用石镐，你会掉耐久）\\n"
"&7② 石炭在 &e石灰窑&7 里烧圆石\\n"
"&7③ 工作台合成炉芯，右键放平地上\\n\\n"
"&c⚠ 坑：石炭熔炉周围 3 格不能有可燃方块，否则一烧就蔓延。\\n"
"&8→ 下一节：用它烧出第一块铁。"
```
背景 → 目标 → 分步 → 坑 → 预告。

### 3.2 详略铁律

| 铁律 | 反面 |
|---|---|
| **写"下一步做什么"，不写百科** | 复制 mod wiki 的物品表进来（玩家不看书会开 JEI） |
| 只写**这个 mod 特有的坑** | 写"挖矿要带火把"这种谁都知道的 |
| 每个 mod 的第一个任务**才需要高档** | 同 mod 第 20 个任务还写 500 字 |
| 用 `&7` 正文 / `&e` 目标 / `&c` 警告 / `&8` 灰色小字 | 全篇一个颜色 |

## 4. 奖励丰富度三档

| 档 | 每任务奖励数 | 构成 | 适合 |
|---|---|---|---|
| **低** | **1 个**，数量小 | 耗材：食物、基础材料 1-8 个、少量 xp | 生存压力本身就是难度（硬核包、群峦风）。奖励多了会毁掉节奏 |
| **中（默认）** | **1-2 个** | 耗材 + 该 mod 的入门件 / 关键材料；里程碑给 2-3 个 | 大多数包 |
| **高** | **2-4 个 + 节点大奖** | `choice`（二选一）/ `random`（权重抽）/ loot crate / `command` 发专属物；**每章收尾一个大奖** | 奖励驱动型（RPG、空岛、抽卡向） |

### 4.1 配平四条

1. **奖励不许跳步**：别在 P1 发 P3 才该有的东西（给了 = 玩家跳过你设计的内容）。
2. **里程碑给"钥匙"，日常给"耗材"**：里程碑奖励应该是**下一阶段的门槛物**（一次铁锭、一个背包）。
3. **高奖励档用"不可合成的便利/装饰"防通胀**：背包升级、飞行券、家具、皮肤 —— 比猛发矿有价值得多。
   狂发原版矿物 = 玩家跳过采矿 = 你设计的矿物 mod 全废。
4. **奖励档与详细度档独立**：
   - 低详略 + 高奖励 = 速通但爽（抽卡向）
   - 高详略 + 低奖励 = 剧情驱动（叙事向）
   - 两者都高 = 新手教学向；两者都低 = 硬核自虐向。**四种组合都成立，选错才叫错**。

### 4.2 奖励写法参考

```snbt
# 低档
rewards: [{ id: "D000000000000001", type: "item", count: 2,
            item: { Count: 2, id: "minecraft:bread" },
            title: "&6奖励：面包 ×2" }]

# 中档：物品 + 经验
rewards: [ { id: "...", type: "item", item: {Count: 8, id: "minecraft:iron_ingot"}, title: "&6铁锭 ×8" }
           { id: "...", type: "xp", xp: 30, title: "&6经验 ×30" } ]

# 高档：抽奖 + 章节大奖（Reward Table 配 loot crate）
rewards: [ { id: "...", type: "random", table_id: "<REWARD_TABLE_ID>", title: "&d随机补给箱" }
           { id: "...", type: "command", command: "/give @p minecraft:diamond_pickaxe{...}", title: "&6本章大奖：钻石镐" } ]
```
> 奖励类型全集（choice/random/loot_table/toast/stage…）见 `FTB_Quests任务编辑.md` §7 尾。
> 大批量改奖励用 `/ftbquests export_reward_table_to_csv` 导成 CSV 批处理。

## 5. 档位怎么选（决策表）

| 包类型 | 目标玩家 | 详细度 | 奖励档 |
|---|---|---|---|
| 科技/机械向（Create、AE2） | 老玩家为主 | **低-中**（写坑不写基础） | 中 |
| RPG / 空岛 / 抽卡向 | 想要正反馈 | 中 | **高** |
| 剧情 / 冒险向 | 看故事来的 | **高** | 中 |
| 硬核 / 生存向 | 自找苦吃 | 低 | **低** |
| 新手友好 / 教学向 | 没玩过 mod | **高**（每 mod 首任务必高） | 中-高 |
| 综合包（150+ mod） | 通吃 | **按阶段混合**：P0 高、P1 中、P2-P3 低 | 中（里程碑升一档） |

> 混合是常态。**别追求全包统一档位**——按阶段/按章节给不同档，玩家体验反而更顺。

## 6. 章节蓝图模板（照抄改）

```
P0 起步（1 章，8-12 任务，详细度高）
  ├ 欢迎 / 这包有什么（checkmark + 一句话列 mod 类别）
  ├ QoL 三件套：地图 / 背包 / 信息显示（教按键）
  ├ 生存基础：木→石→铁（原版链，给耗材）
  └ ★里程碑：住进第一个家 → 发钥匙（背包升级）

P1 立足（1 章，12-20 任务，中）
  ├ 存储线：第一台存储 → 升级 → 物流
  ├ 电力/能源线（如有）
  ├ 农牧线：食物 / 动物 / 附魔
  └ ★里程碑：基地成型 → 发钥匙（该线一阶产物）

P2 分线（3-5 章，每章 15-30 任务，低-中）
  ├ 【科技章】按机器链：基础件 → 中间件 → 产线 → 自动化
  ├ 【魔法章】按等级：一阶法术 → 材料 → 二阶 → 祭坛
  ├ 【探索章】按区域/结构：主世界结构 → 下界 → 末地（structure/dimension 任务）
  ├ 【战斗章】Boss 图鉴（每 Boss 一条 kill 任务）
  └ 【生活支线】装饰 / 食物 / 收集（optional: true）

P3 终局（1-2 章，10-20 任务，低）
  ├ 每线的终局目标（该 mod 的最强物品）
  ├ 跨线联动任务（科技产物 → 魔法材料 之类）
  └ ★终章大奖
```

**任务数量级**：100 个模组的包 → 200-400 个任务比较合适。低于 150 个基本不可能做到覆盖度 100%。
